# 测试项目统一与 Web 可用性设计

日期：2026-07-30

现行事实源仍以 `docs/design/` 下的架构、契约和测试规范为准；本文记录本轮已确认的变更决策，实施完成后由事实源描述最终行为。

## 1. 串口测试

- 将 BUS 内部回环与 PC-DUT 外部回显合并为一个用户可见的“串口测试”，使用单配置、单复合算法和 BIZ `single`。
- 参数为测试方式（回环/回显）、测试串口（COM1/COM2/COM4）和循环次数（`1..100000`，默认 `1000`）。
- 回环继续使用 `03/01`，一次请求把循环次数传给 DUT；回显使用 `03/02`，由复合算法在一次 BIZ 运行内执行指定轮数，每轮保留 5 秒事务截止时间并在轮间检查停止。
- 回显模式要求用户从系统枚举结果中选择独立的本地 PC 串口；回环模式不使用该端口。主控制口与辅助口不得相同。
- 旧 BUS 配置不再进入当前测试目录清单；旧算法 ID 保留兼容受控外部旧配置。

## 2. DH 点火参数

- `power_enable` 与 `return_enable` 在 Web 中以复选框编辑，分别把未选/选中映射为协议数值 `0/1`，不改变 U8 线编码。
- 23 路 `channel_enabled[]` 提供全选和全不选操作。
- `delay_frames` 的中文标签改为“等待帧数”，其“N 帧基线后在下一帧采样前点火”的协议语义不变。

## 3. DI/DO 与 PXI-6259

- 当前配置无条件需要的 PXI 资源统一在应用 `prepare`（Web“连接设备”）阶段打开并保持到断开，Adapter、DLL、MAX 名称或序列号错误在该阶段返回。
- DO 测试名称统一为“数字量输出”，只支持 BIZ `single`。
- Web 显示 16 路 DO。DO5/DO6 禁用并固定为 0；DO3/DO4 为低有效电源使能，默认原始位为 1（关闭），但允许用户显式修改；其他位正常编辑。
- 每次运行只发送一组用户掩码。算法检查完整 DUT `applied_state`，等待既有 `100 ms`，再用 PXI-6259 P0.3/P0.4 验证 bit2/bit1。其余位只具备 DUT 回读证据，界面明确标注“未配置外部回读”。
- 协议、DUT 或 PXI I/O 错误为 Error；完整回读或两路物理读回不一致为 Fail。
- 运行完成、停止或断开均不发送额外 DUT DO 复位，产品保持最后一次用户配置状态。

## 4. 定时器与共性界面

- 定时器页面展示八桶分布：`[0,2)`、`[2,4)`、`[4,8)`、`[8,16)`、`[16,32)`、`[32,64)`、`[64,100)`、`[100,+∞)` µs。阈值属于后一桶，统计的是实际相邻周期与 250 µs 期望周期之差的绝对值。
- 展示各桶计数和合计；字段缺失、类型/范围非法或成功响应合计不为 250 时显示不完整警告，但不新增或改变 Pass/Fail 判据。
- 优先使用实时样本，终态重连时回退到 `snapshot.rawData.responseValues`。
- 删除运行条中的浏览器接收/缓存/淘汰/序号状态文字，但保留内部遥测诊断数据。
- PC 周期只显示简短“间隔”标签和 `ms` 单位，删除可见说明并保证输入区域不拥挤。

## 5. 验证边界

- 行为变更先由失败回归测试锁定，再实施最小代码。
- 覆盖算法参数、串口两种路由、停止与错误归约、DO 掩码/禁用位/6259 判定、DI/DO prepare 生命周期、WebSocket 动作与 DTO、React 交互和定时器快照回退。
- 修改 `front/` 后运行 `npm test` 与 `npm run build`；宿主运行相关 CTest 后再运行 Windows 集成入口。
- Fake NI-DAQmx、Mock、协议或浏览器自动化均不提升为真实 PXI、真实串口或目标板验收证据。
