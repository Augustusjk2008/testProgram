# DO_WRITE 与舵机板级自动测试设计

> 状态：设计已由用户确认，已实现并完成自动化验证。
> 现行事实最终以架构、协议契约、测试规范和已核对实现为准。

## 目标与边界

新增 `mbddf.do_write` 和 `mbddf.helm_board_test` 两项宿主测试。两项测试都复用
MB_DDF 当前产品协议，不修改 DUT 命令布局；自动模式通过 PXI 板卡闭环验证真实端口，舵机板级
测试同时保留不操作板卡的手动模式，供没有 PXI 板卡时配合外部仪器测量。

本轮不把逻辑电平采集表述为电压精度验收，不控制独立 `MB_DDF_v2_HelmControl` 进程，不把
软件/Fake 自动化当成真实台架验收，也不生成独立板级测试结果文件。结果保存在当前后端进程的
内存快照中，下一轮覆盖，服务重启后丢失。

PXI/PXIe-6259（A3）使用以下端点：

| 资源 | 6259 端点 | 连接器针脚 | DUT 信号 |
|---|---:|---:|---|
| 数字刺激 | P0.0 | 52 | DI3，PLL 锁定 |
| 数字刺激 | P0.1 | 17 | DI1，保险告警 |
| 数字刺激 | P0.2 | 49 | DI2，保险点火指令 |
| 数字采集 | P0.3 | 47 | DO2，发送使能 |
| 数字采集 | P0.4 | 19 | DO1，衰减器控制 |
| 模拟采集 | AI0..AI3 | 68/33/65/30 | PWM1..PWM4 |
| 模拟采集 | AI4..AI7 | 28/60/25/57 | DIR1..DIR4 |

PXI-6733（A4）本轮只使用 AO0..AO3（针脚 22/21/57/25）驱动 FK1..FK4；AO4..AO7
保留在设备能力范围内，但备用反馈链路不纳入本轮测试。AI 端接按接线表的独立信号与 AI GND
采用 RSE。6259 与 6733 的 MAX 设备名及序列号保持 `CONFIGURE_ME` 门禁，真机自动测试前必须
由现场配置，不允许用猜测值绕过。

现有 DI 配置中把 P0.0..P0.15 全部当作刺激输出不符合接线表。配置应改成只驱动 P0.0、P0.1、
P0.2；DI0 联锁和 DI8 释放许可只通过 DUT 总线回读，不由 PXI 自动刺激。

## DO_WRITE 自动闭环

测试固定从安全基线掩码 `0x0018` 开始，按以下五步写入：

```text
0x0018 -> 0x001C -> 0x0018 -> 0x001A -> 0x0018
```

每次 DUT 应答后先核对 `applied_state`，固定等待 100 ms，再读取 6259 P0.3/P0.4。P0.3
对应 DO2，P0.4 对应 DO1。数字采集只判定 0/1 是否与当前掩码一致，不宣称完成
`<=0.8 V`/`>=3.8 V` 的真实电压验证。

命令不重试。协议、通讯、DUT 非零错误和 HAL 错误使结果为 Error；物理逻辑不一致记为 Fail，
但继续完成剩余步骤以生成完整矩阵。正常最后一步回到 `0x0018`；异常路径不追加清理写入，保留
最后一次成功或未知状态。

## HELM_BOARD_TEST 模式

同一测试配置通过非持久化运行参数 `test_mode` 选择自动或手动，默认自动，只支持 `single`。

手动模式编辑四路 PWM 占空比（0..100）和四路方向位，发送一次 `07/02`，不打开、不读写
6259/6733，只显示协议响应表。界面不添加“DUT 内部自检”等额外说明。

自动模式要求现场先停止独立舵控程序；界面提供互斥提示，但软件不增加第二次确认、进程探测或
强制互锁。自动测试按方向、PWM、反馈三阶段执行，判据不匹配继续采点，通讯/协议/HAL 错误或
用户停止才中断。

### 方向阶段

四路 PWM 全部为 0，依次发送方向掩码 `0000`、`0001`、`0010`、`0100`、`1000`。每次写入
后由 6259 AI4..AI7 采样，低电平判据 `<=0.8 V`，高电平判据 `>=3.8 V`。每路方向 0 和 1
至少各覆盖一次，方向与 PWM 不耦合判定。

### PWM 阶段

四通道顺序测试，非目标通道保持 0。每路测试点为
`1, 5, 10, 25, 50, 75, 90, 95, 99 %`，共 36 点。6259 对目标 AI 通道以
1.25 MS/s 有限采样，采集至少 20 个完整 4 kHz 周期。算法检查低平台 `<=0.8 V`、高平台
`>=3.8 V`，用自适应中点阈值与插值边沿计算占空比，允许误差 `±1.0` 个百分点。频率只展示，
不参与 Pass/Fail；完整周期不足或非目标通道出现脉冲/串扰记为 Fail。

### 反馈电压阶段

6733 AO0..AO3 顺序激励，每次仅目标通道非零，其他 AO 为 0。每路从 0.0 V 到 5.0 V，步长
0.5 V，共 44 点。设置 AO 后等待 100 ms，只发送一次 `07/02` 快照，对应
`helm_AD_value` 与命令值比较，容差 `±0.05 V`；5.0 V 的协议期望值使用可编码上限
（约 4.99985 V）。

所有完成、Fail、停止和 Error 路径都尽力将 AO0..AO3 写回 0 V。清理失败不能产生 Pass，
最终记 Error/安全状态未知。协议命令不自动重试。正常结束时 DUT 最后一次命令为 PWM 全零、
方向全零，但保持 `07/02` 原有使能语义；异常路径不向 DUT 追加状态清理命令。

## 分层实现

- 算法层新增两个专用执行器和板级夹具抽象，负责产品序列、判据、结果和停止点。
- 应用组合根在运行参数规范化后按模式绑定辅助 HAL 设备：DO 自动测试需要 6259；舵机自动模式
  需要 6259 与 6733；手动模式不打开辅助板卡。
- `ni.daqmx` Adapter 保持 C ABI v1，内部改为型号 profile。6259 保持现有能力；6733 本轮只
  暴露 AO0..AO7 与所需安全写零能力，不宣称未验证的 AI/DIO/counter 能力。
- BIZ 仍使用通用 `single` 语义，不解释板级测试参数或物理判据。
- WebSocket 不新增专用动作；执行中逐点发布 sample，完整版本化结果位于
  `snapshot.rawData.boardTest`。

板级结果契约使用 `schema=hwtest.mbddf-board-test-result`、`version=1`，包含类型、模式、完成点
计数、汇总以及 `doSteps`、`directionPoints`、`pwmPoints`、`feedbackPoints` 或手动响应。前端
提供专用板级测试页，展示步骤/方向矩阵、指令与实测曲线、误差和容差、最大误差与最差点；最终
状态仍由既有 Pass/Fail/Error/Cancelled 表达。

## 错误与停止语义

- 物理判据不满足：记录失败点并继续采集，最终 Fail。
- 通讯、协议、DUT 非零状态、HAL 或 AO 清理失败：立即结束，最终 Error。
- 用户停止：只在点间响应，执行 AO 清零后为 Cancelled。
- 不自动重试写命令，不隐式启动或停止外部舵控程序。

## 验证边界

自动化必须覆盖协议序列、无重试、Fail 继续、Error 中断、停止点、PWM 算法、反馈容差、方向矩阵、
AO 全路径清零、手动模式零板卡访问、配置门禁、结果投影和浏览器展示。真实验收另行记录机箱、
MAX 身份、线缆/针脚、共地、隔离、电平、采样参数、四通道曲线、最差点、停止与清零结果。
