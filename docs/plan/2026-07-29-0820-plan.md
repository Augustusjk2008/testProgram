# 舵机连续测试性能分析与伯德图实施计划

## 1. 实施目标

以现有[舵机性能分析设计说明](</H:/WorkSpace/QtWorkspace/testProgram/docs/superpowers/specs/2026-07-29-servo-performance-analysis-design.md>)为基线，在 `mbddf.helm_stream` 连续测试停止并完成硬件收尾后：

1. 自动封存四路舵机完整分析输入。
2. 在后台线程计算通用指标和波形专用指标。
3. 连续扫频时计算频响、带宽、指定频点相位、共振峰并生成伯德图数据。
4. 持久化版本化性能 JSON。
5. 通过 WebSocket v1 投影分析进度、摘要和按通道曲线。
6. 在 Web 前端增加“性能”页面，展示计算过程、指标、告警和伯德图。
7. 保证分析结果不修改现有采集 `Pass/Fail`、错误码或硬件停止语义。

本轮实施不增加丢样补偿、补点、重采样或基于流水号的分析拒绝逻辑。

## 2. 已冻结的产品与交互口径

以下口径直接作为实现和测试契约：

- 支持正弦、方波、三角波、恒值、连续对数扫频五种波形。
- 伯德图只在连续扫频时生成。
- 扫频仍由用户手动 STOP，不增加自动停止。
- 输入使用 `ins[0..3]` 指令回显，输出使用 `fdb[0..3]` 反馈。
- 原始计算时间轴使用 `streamElapsedUs`，不使用 PC 到达时间。
- 不对原始样本插值、补点或重采样；派生交点可以在同一连续有效频段内插值。
- 产品帧、DDS 和串口流水不连续只计入诊断，不影响数值和通道状态。
- `snapshot.analysis` 用于广播小型状态和摘要。
- `analysisResult` 是按通道读取伯德数组的只读 WebSocket action；两者同时存在、职责不同。
- `analysisResult` 成功回复新增独立的出站 16 KiB 上限；不能把现有入站 16 KiB 测试当作证明。
- WebSocket 真正断开、`disconnect`、`quit`、`DropCleanup` 会取消分析；仅切换 SPA 页面不会取消。
- 新任务只有启动成功后才清除上一轮结果；启动失败保留旧结果。
- TUI、Qt GUI、DUT、HAL 和 BIZ 本轮不增加性能业务代码。

## 4. 公共数据与状态契约

### 4.1 能力描述

`TestDescriptor` 尾部追加：

```text
postRunAnalysis:
  supported
  analyzerId        = "mbddf.helm.performance"
  schemaVersion     = "1"
```

非舵机配置和旧配置安全回退为 `supported=false`。

### 4.2 分析身份

每轮分析使用：

```text
{taskId, analysisGeneration}
```

其中：

- `analysisGeneration` 是协调器自己的单调计数，不复用控制器已有 lifecycle generation。
- 只在 `startTestWithOptions()` 成功返回新 `taskId` 后递增。
- 所有捕获、进度、结果、文件提交和查询都必须校验完整身份。
- 旧线程的迟到回告不得覆盖当前快照。

### 4.3 分析状态

整体状态：

```text
none
capturing
queued
validating
preprocessing
calculating
persisting
completed
partial
unavailable
failed
cancelled
```

逐通道只允许：

```text
not_applicable
completed
partial
unavailable
```

`failed/cancelled` 只作为整体基础设施状态，不携带半成品曲线。

### 4.4 指标编码

指标统一使用显式结构：

```text
key
label
unit
status
value | null
detail
```

禁止：

- 用 `0` 代替无效幅值或相位。
- 用字符串保存数值。
- 输出 NaN 或 Inf。
- 跨无效频点空洞插值或连线。

无效伯德点使用 `null + pointStatus`，四个数组长度保持一致。

## 5. 后端资源默认值

在 `dataStorage.analysis` 中加入首版默认值，并写边界测试：

```json
{
  "maxCaptureBytes": 536870912,
  "maxInputSamples": 5000000,
  "maxAnalysisDurationS": 3600,
  "minFreeBytes": 1073741824,
  "analysisTimeoutMs": 30000,
  "analysisShutdownTimeoutMs": 5000,
  "maxResultBytes": 16777216,
  "maxProjectedPoints": 256,
  "maxProjectedBytes": 16384,
  "maxAnalysisSummaryBytes": 8192,
  "diagnosticRetentionDays": 7
}
```

约束：

- 浏览器无权覆盖这些值。
- 达到捕获上限时停止接收分析输入，最终为 `unavailable/analysis_resource_limit`，但硬件流、STOP、TXT 和 verdict 继续。
- 结果 JSON 或预生成曲线投影无法满足大小限制时为 `failed`，不得静默截断后标成完整。
- 单通道警告最多 16 条，单条最多 512 UTF-8 字节。

## 6. 详细实施步骤

### 阶段 0：建立基线并冻结契约

1. 舵机测试目前会报“helm DDS command write was incomplete”，先解决这个问题。
2. 执行当前算法、应用、WebSocket 和前端基线测试。
3. 固定 analyzer ID、Schema 版本、状态、原因码、资源上限和波形编号。
4. 明确 `snapshot.analysis` 与 `analysisResult` action 两套契约。
5. 固定断线取消、SPA 导航不取消和手动 STOP 规则。
6. 为所有新增公共结构采用尾部扩展，维持 Qt 5.15 和 Qt 6 fallback。

退出门槛：协议、状态真值表和资源阈值均能直接转成测试断言。

### 阶段 1：先建立算法接口与独立 fixture

1. 新建 `post_run_analysis.h`，定义：

   - `PostRunSample`
   - `AnalysisIdentity`
   - `AnalysisSessionSpec`
   - `AnalysisTermination`
   - `AnalysisInputSeal`
   - `AnalysisProgress`
   - `AnalysisCancelToken`
   - `AnalysisResult`
   - `IPostRunAnalysisSession`
   - `IPostRunAnalyzer`

2. 新建 `tests/algorithm/fixtures/helm_performance/`：

   - 每种波形的输入、元数据和期望结果。
   - 一阶低通、二阶欠阻尼、纯时延扫频。
   - 正向/反向、完整/提前停止/尾段截断。
   - `manifest.json` 记录 SHA-256、生成方法、参数、容差和 analyzerVersion。

3. fixture 期望值使用独立解析公式或独立生成脚本，不调用待测分析器代码。
4. 先提交失败的接口、捕获格式和状态归约测试，再实现生产代码。

退出门槛：fixture 可追溯，测试能在没有控制器和 Web UI 的条件下独立运行。

### 阶段 2：实现流式分析捕获

1. 应用存储层在调用 BIZ start 前：

   - 创建固定分析子目录。
   - 检查可写性和最小磁盘余量。
   - 用随机 token 创建 pending 捕获文件。
   - 构造算法层分析会话。

2. pending 文件创建失败时返回 `analysis_storage`，不启动硬件任务，旧结果不清除。
3. BIZ start 成功后：

   - 获取新 taskId。
   - 递增 analysisGeneration。
   - 将 pending 会话绑定到新身份。
   - 清除上一轮投影并进入 `capturing`。

4. 捕获文件使用版本化固定小端二进制格式：

```text
magic + formatVersion + recordBytes + metadata
RecordV1...
footer + acceptedCount + lateCount + normalizedInputSha256
```

5. `RecordV1` 至少保存：

   - 内部接受序号、`streamElapsedUs`
   - `ins[4]`、`fdb[4]`
   - `status`、`err_code`
   - 自检、timeout
   - 产品帧和串口流水诊断
   - 批内索引

6. 在控制器 `sampleProduced` 内部路径按以下顺序处理：

```text
ContinuousDataRecorder.append
PostRunAnalysisCoordinator.append
公开 sampleReceived 投影判断
```

这样 STOP 等待期间、公开投影已抑制的尾样本仍能进入分析。

7. 只接受当前身份且 `stepId=HELM_STREAM` 的样本。
8. 封存后迟到样本只增加 `lateSampleCount`，不能修改输入。
9. 流水号变化只更新诊断字段，不改变计算输入和状态。

退出门槛：捕获 round-trip、上限、错误注入、封存不可变和流水诊断测试全部通过。

### 阶段 3：实现通用指标和四种非扫频波形

按风险从低到高实施：

1. 恒值：

   - 要求有效时长 `D >= 1 s`。
   - 使用尾部稳定窗口。
   - 输出均值误差、标准差、峰峰值和最大偏差。
   - 零目标不套用动态激励阈值。

2. 正弦：

   - 丢弃前两个完整周期，至少保留三个周期。
   - 使用实际 DDS 时间做加权最小二乘拟合。
   - 输出输入/反馈幅值、增益、主值相位差和主值等效时延。
   - 相位统一定义为 `φcmd-φfdb`，包裹到 `[-180°,180°)`。

3. 方波：

   - 从实际 `ins` 检测平台和边沿。
   - 平台中间 50% 求稳态中位数。
   - 反馈用局部线性插值求 10%/90% 穿越时间。
   - 输出延迟、上升/下降时间、超调、稳定时间、稳态误差。
   - 尾部不完整边沿不参与专用指标。

4. 三角波：

   - 使用实际 DDS 时间计算方向。
   - 导数死区为本周期中位绝对斜率的 5%。
   - 排除顶部和底部各 10%。
   - 输出正反方向斜率比、RMSE、最大误差、不对称性及 32 分箱方向性跟踪差。
   - UI 名称固定为“方向性跟踪差（含动态滞后）”。

5. 所有波形共同输出样本数、有效时长、输入/反馈范围、误差均值、RMSE、最大绝对误差和相关系数。
6. 激励阈值固定为：

```text
max(1e-6 degree, abs(configuredAmpl) * 0.01)
```

等于阈值可计算但增加 `near_excitation_floor`；低于阈值不可计算。

退出门槛：四类 golden、阈值边界、周期不足、禁用通道、自检/timeout 和整体状态归约全部通过。

### 阶段 4：实现扫频局部同步估计

不实现整段 FFT；使用设计中确定的扫频相位律和局部同步复数估计。

1. 校验 `f0>0`、`f1>0`、`T>0` 和 Nyquist 条件。
2. `f0==f1` 时转为单频正弦结果，不生成伯德图或带宽。
3. 拟合 `tCommandStartUs`：

   - 候选范围为 `[firstSampleUs-T, lastSampleUs]`。
   - 先由实际有效激励区间收紧候选范围。
   - 用最多 2048 个按时间分层选取的原始样本计算候选相关性。
   - 粗搜索最多 32768 个候选，保留最优局部峰后在原始样本间隔附近细化。
   - 搜索无法在限制内形成唯一稳定最优值时返回 `command_model_ambiguous`，不进行无界计算。
   - 最佳相关系数低于 0.95 时返回 `command_model_mismatch`。
   - 并列时依次选择重叠时间更长、起点更早者。
   - 保存最佳/次佳相关系数、重叠时长和候选范围。

4. 在 `0..100 ms` 内扫描原始样本配对，估计非负粗时延 `delay0`；不生成新采样点。
5. 根据四周期相位窗口生成最多 256 个对数频点。
6. 命令窗口必须完整覆盖；反馈完整性使用 `maxDelayMs` 保护，而不是只使用估计的 `delay0`。
7. 使用实际 DDS 时间的梯形权重和相位域 Hann 权重计算：

```text
C = Σ(q*w*(x-mean_w(x))*exp(-j*phase)) / Σ(q*w)
H = (Cfeedback/Ccommand) * exp(-j*2πf*delay0)
```

8. 对有效点按频率升序保存；相位只在每个连续有效段内部解包。
9. 低频基准 `G0` 只允许来自包含计划低频锚点的连续有效段。
10. -1/-3 dB、5/10/20 Hz 相位和共振峰只在同一有效段内插值或搜索。
11. 正扫提前停止时尾部高频受影响；反扫时尾部低频受影响。
12. `plannedUsableBand`、实际覆盖频段、无效原因和阈值全部写入结果。

退出门槛：一阶低通、二阶共振、纯时延、正反向、弱激励、相位空洞、提前 STOP 和尾段截断 fixture 全部通过。

### 阶段 5：实现协调器、线程和持久化

1. `PostRunAnalysisCoordinator` 常驻控制器亲和线程。
2. 采集终态建立关闭栅栏：

   - 记录最后接受序号。
   - 等待全部追加完成。
   - flush、关闭捕获文件。
   - 生成不可变 `AnalysisInputSeal`。

3. 用户 STOP 使用双栅栏：

   - 捕获已封存。
   - `stopCompleted` 已完成硬件收尾。

   两者都满足后才启动性能线程；自然 `finished` 只等待捕获封存。

4. 先发送 `stopCompleted`，再排队启动分析线程，确保 STOP 回复不承担性能计算时间。
5. 采集以 `error` 结束时只保留诊断输入，分析为 `unavailable`，不包装故障前数据。
6. 使用一次性 QThread 工作对象：

   - 仅持有不可变上下文、封存输入和原子取消令牌。
   - 不访问 controller、BIZ、HAL 或 WebSocket QObject。
   - 进度和结果用 queued connection 回到控制器线程。
   - 在读块、逐通道、逐频点和持久化前检查取消。

7. 结果使用 `QSaveFile`：

   - 文件名含 taskId 和 generation。
   - 先验证最大结果大小。
   - commit 成功后才能发布 `resultFilePath`。
   - 成功后删除临时捕获。
   - 失败后按保留策略留下 `diagnosticInputFilePath`。

8. 若原始 TXT 成功保存，工作线程计算 TXT SHA-256，并记录路径和哈希；否则结果标记 `reproducible=false`。
9. shutdown/断线：

   - 请求协作取消。
   - 等待配置的 join 时限。
   - 超时返回 `analysis_shutdown_timeout` 并保留仍被线程引用的对象。
   - 禁止 `QThread::terminate()`、detach 或删除运行中的线程。
   - 控制器析构前最终确认线程退出。

退出门槛：STOP 不等待分析、身份去重、取消竞争、超时、原子文件和故障注入测试全部通过。

### 阶段 6：接入控制器 DTO 和动作门禁

1. `ApplicationSnapshot` 尾部追加 `analysis`：

   - 身份、状态、进度、阶段、消息。
   - 结果/诊断路径。
   - 输入摘要。
   - 四个通道的小型摘要。
   - 不包含伯德完整数组。

2. 为控制器增加只读通道结果查询接口。
3. `mbddf.helm_stream` 在注册表声明分析能力；其他算法无能力。
4. 分析门禁从 `queued` 开始生效：

   - 拒绝 load/select/prepare/start、资源选择和其他新会话写动作，返回 `command_in_progress`。
   - `capturing` 期间仍允许当前任务 STOP。
   - shutdown/disconnect/quit 始终允许，并执行取消。
   - snapshot、配置列表、控制资源、端口和合法的 `analysisResult` 保持可读。

5. 任何分析状态不得修改：

   - `snapshot.phase`
   - `snapshot.verdict`
   - 采集 `errorCode`
   - `biz::TestResult`

7. 伯德图：

   - 增加 -1/-3 dB、5/10/20 Hz 和共振峰标记。

8. 性能页只使用后端 `analysisResult`，不得读取 50,000 点 `SampleBuffer` 计算性能。

退出门槛：协议解析、缓存身份、自动导航一次、空洞模型和生产构建测试通过；手工浏览器 smoke 验证布局和游标。

## 10. 主要风险与控制措施

| 风险 | 控制 |
|---|---|
| STOP、尾样本和分析启动竞态 | 捕获封存与 stopCompleted 双栅栏；身份去重 |
| 工作线程退出时对象被释放 | 协作取消、安全 join、禁止 terminate/detach |
| 长时手动运行占满内存或磁盘 | 流式二进制捕获、四类输入上限和磁盘余量检查 |
| 扫频起点搜索计算量失控 | 有效激励收窄、候选数上限、分层样本和歧义时安全拒绝 |
| 弱输入产生伪造的 0 dB/0° | 显式激励阈值、upper_bound/indeterminate 状态 |
| 相位跨空洞错误解包 | 只在连续有效段内解包和插值 |
| 反向扫频裁错频段 | 按时间方向判断扫频终止侧，并设置独立 golden |
| 快照或曲线消息过大 | 摘要与曲线分离、确定性抽样、真实出站字节测试 |
| 新任务显示旧结果 | taskId+generation 缓存、成功 start 才清除、旧回复丢弃 |
| 性能结果污染采集结论 | sidecar result，不进入 BIZ TestResult 或 verdict |

## 11. 完成标准

满足以下全部条件才视为实施完成：

- 五种波形均有可追溯算法测试。
- 扫频伯德图使用实际 DDS 时间和局部同步复数估计。
- 不存在丢样补偿、补点、重采样或流水门禁。
- STOP 不等待性能计算。
- 捕获包含 STOP 尾样本且 seal 后不可变。
- 分析结果不改变 Pass/Fail。
- 成功结果以原子 JSON 文件保存。
- WebSocket v1 保持向后兼容，出站分析回复不超过 16 KiB。
- Web 性能页不使用 50,000 点实时缓存作为分析输入。
- 断线取消、线程退出、资源限制和竞态均有自动化证据。
- Debug、Release、前端测试与生产构建全部通过。
- 事实源、测试规范和实施状态同步完成。
- 本轮计划阶段只进行了只读分析，没有修改项目文件。
