# Qt 5.15 WebSocket Backend Implementation Plan

> **已被替代：** 本计划已执行完成。现行实现事实以 `src/app/web/`、根与应用 CMake、`docs/design/contracts/websocket-frontend-protocol.md` 和 `docs/design/testing/testing-specification.md` 为准；下列复选框保留为历史执行记录，不作为当前接口事实源。

> **Execution note:** 本计划可直接按复选框逐步执行。本轮只输出方案，不修改或创建文件。

**Goal:** 保持 Qt 5.15，新增基于 `QWebSocketServer` 的 `hwtest_web` 后端，并在仓库根目录创建仅含说明文件的 `front/` 目录；不实现任何前端页面、组件或构建工具。

**Architecture:** `hwtest_web` 是与 TUI、GUI 并列的独立进程，拥有一个 `TestApplicationController`。WebSocket 层只负责 JSON 协议、连接和控制器动作适配，通过 queued invocation 调用控制器，不直接依赖 BIZ、算法、HAL 或设备 I/O。

**Tech Stack:** C++17、Qt 5.15 Core/Network/WebSockets、Qt 6 WebSockets fallback、CMake、GoogleTest、CTest、PowerShell。

---

## 目标边界

- Qt 仍优先选择 5.15，不提高最低版本，也不切换现有工具链。
- 只监听 `127.0.0.1`，默认端口 `8765`，测试使用端口 `0`。
- 首版只允许一个活跃客户端，第二个客户端收到 `server_busy` 后关闭。
- 不使用数据库、TLS、登录系统、JWT 或远程访问。
- 不提供 HTTP 或静态文件服务；`QWebSocketServer` 只暴露 `/ws`。
- `front/` 只创建 `README.md`，不创建 `package.json`、HTML、CSS、JS、TypeScript 或 Vite 配置。
- 不修改 `TestApplicationController` 公共 API，不修改 BIZ、算法、HAL。
- 不调用 `waitForTerminal()`；停止和断开使用 `stopAsync()`、`stopCompleted`、`shutdown()`。
- 浏览器连接断开时执行安全停止和会话收尾，服务器随后继续监听新连接。

## 协议约定

仅接受 UTF-8 JSON 文本消息，单条输入上限 16 KiB：

```json
{"v":1,"type":"request","id":"req-1","action":"start","params":{}}
{"v":1,"type":"reply","id":"req-1","ok":true,"code":"","message":"","data":{}}
{"v":1,"type":"snapshot","seq":12,"snapshot":{"phase":"running","progress":25}}
{"v":1,"type":"hello","server":"hwtest_web","protocolVersion":1}
```

动作固定为：

| action | 行为 |
|---|---|
| `load` | 使用进程启动时的 `FrontendLaunchOptions`，不接受客户端文件路径 |
| `snapshot` | 返回当前完整快照 |
| `controls` / `ports` | 返回控制资源或宿主串口 |
| `selectControl` / `selectSerialPort` | 调用现有选择 API |
| `prepare` / `start` / `pause` / `resume` | 调用对应控制器动作 |
| `stop` | 调用 `stopAsync()`，在 `stopCompleted` 后回复 |
| `disconnect` | 必要时先异步停止，再 `shutdown()`；服务器继续监听 |
| `quit` | 完成相同安全收尾，然后关闭服务器和进程 |

错误码由 Web 层固定 `invalid_json`、`invalid_envelope`、`unsupported_version`、`unknown_action`、`missing_field`、`server_busy`、`message_too_large`；控制器错误码原样放入 reply。

## Task 5：接入控制器动作和安全收尾

**Files:** `web_socket_frontend_server.cpp`、`web_socket_frontend_server_test.cpp`

- [ ] 所有请求通过以下模式投递，禁止 `BlockingQueuedConnection`：

```cpp

    m_controller,
    [this, request] { executeRequest(request); },
    Qt::QueuedConnection);
```

- [ ] `load` 只调用 `configureController(*m_controller, m_launchOptions)`。
- [ ] `snapshot` 使用 Web 层缓存；`controls`、`ports` 在控制器亲和线程读取。

- [ ] `stop` 保存待完成 request ID，调用 `stopAsync()`，只在 `stopCompleted` 后回复。
- [ ] 存在待完成停止或断开时，新的写动作回复 `command_in_progress`；快照查询仍允许。
- [ ] `disconnect` 和客户端掉线按 `running/paused -> stopAsync -> stopCompleted -> shutdown` 顺序收尾。
- [ ] `quit` 完成相同收尾后关闭监听，发送最终 reply，再排队退出 `QCoreApplication`。
- [ ] `snapshotChanged` 始终广播完整快照；禁止调用 `waitForTerminal()`。
