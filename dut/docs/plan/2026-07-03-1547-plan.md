# CAN RS422 Hardware Loopback Implementation Plan

> **Execution note:** 本方案只在 `src/MB_DDF_HW` 增加独立硬件 Device 层，不把实现放回 `src/MB_DDF`，不改 DDS Core。步骤使用 checkbox (`- [ ]`) 跟踪。

**Goal:** 在 v2 的硬件层中加入 CAN 与 RS422 设备实现，并基于 XDMA 对端的原版 MB_DDF 寄存器流程完成板端回环测试。

**Architecture:** `Core <- Os <- Transport <- Device`。CAN/RS422 只依赖 `MB_DDF::HW::ITransport`，寄存器偏移和操作顺序对齐原版 `H:\Resources\RTLinux\Demos\MB_DDF\src\MB_DDF\PhysicalLayer\Device\CanDevice.*` 与 `Rs422Device.*`。测试分两层：无硬件单测验证寄存器写序，硬件 smoke 二进制在目标板上验证真实回环。

**Tech Stack:** C++20、CMake、PowerShell、AArch64 交叉编译、XDMA `/dev/xdmaN_user` + events fd、GoogleTest、板端 SSH/SCP。

---

## 目标

1. 新增 `src/MB_DDF_HW/Device`，实现 CAN classic 与 RS422 设备层。
2. CAN 复用原版 AXI CAN FIFO 流程：
   - 默认 XDMA offset `0x50000`
   - 默认 event `5`
   - raw frame 格式 `[id:4 little][flags:1][dlc:1][data:dlc]`
   - loopback、bit timing、accept-all filter、TX/RX FIFO 流程保持原版语义。
3. RS422 复用原版 BRAM/寄存器流程：
   - 默认 YX offset `0x00000`、event `0`
   - 默认 IMU offset `0x10000`、event `1`
   - 默认 DYT offset `0x20000`、event `2`
   - `SEND_BUF=0x100`、`RECV_BUF=0x000`、`CMD_TX=0x81`、`CMD_RX=0x82`
   - loopback 通过 `LPB_reg=0x20C` 配置。
4. 新增板端回环 smoke test，可单独跑 CAN、RS422 或两者一起跑。
5. 默认 DDS-only 构建仍不构建硬件层。

## Task 2: 实现 CAN classic 设备

**Files:**

- Create: `src/MB_DDF_HW/Device/CanRegisters.h`
- Create: `src/MB_DDF_HW/Device/CanFrame.h`
- Create: `src/MB_DDF_HW/Device/CanDevice.h`

- [ ] **Step 1: 写入 CAN 寄存器常量**

从原版 `pl_can.h` 迁移这些常量到 `MB_DDF::HW`：

```cpp
constexpr uint64_t XCAN_SRR_OFFSET = 0x000;
constexpr uint64_t XCAN_MSR_OFFSET = 0x004;
constexpr uint64_t XCAN_BRPR_OFFSET = 0x008;
constexpr uint64_t XCAN_BTR_OFFSET = 0x00C;
constexpr uint64_t XCAN_SR_OFFSET = 0x018;
constexpr uint64_t XCAN_ISR_OFFSET = 0x01C;
constexpr uint64_t XCAN_IER_OFFSET = 0x020;
constexpr uint64_t XCAN_ICR_OFFSET = 0x024;
constexpr uint64_t XCAN_TX_ID_OFFSET = 0x030;
constexpr uint64_t XCAN_TX_DLC_OFFSET = 0x034;
constexpr uint64_t XCAN_TX_DW1_OFFSET = 0x038;
constexpr uint64_t XCAN_TX_DW2_OFFSET = 0x03C;
constexpr uint64_t XCAN_RX_ID_OFFSET = 0x050;
constexpr uint64_t XCAN_RX_DLC_OFFSET = 0x054;
constexpr uint64_t XCAN_RX_DW1_OFFSET = 0x058;
constexpr uint64_t XCAN_RX_DW2_OFFSET = 0x05C;
constexpr uint64_t XCAN_AFR_OFFSET = 0x060;
constexpr uint64_t XCAN_AFMR1_OFFSET = 0x064;
constexpr uint64_t XCAN_AFIR1_OFFSET = 0x068;
```

同时迁移 `SRR/MSR/SR/ISR/IER/ICR/AFR/ID/DLC` 掩码，保持原版数值。

- [ ] **Step 2: 定义 `CanFrame`**

```cpp
struct CanFrame {
    uint32_t id{0};
    bool ide{false};
    bool rtr{false};
    uint8_t dlc{0};
    std::array<uint8_t, 8> data{};
};
```

- [ ] **Step 3: 实现 raw frame 编解码**

`CanDevice` 提供：

```cpp
static Result<CanFrame> decode_raw_frame(BufferView data);
static Result<size_t> encode_raw_frame(const CanFrame& frame, MutableBufferView out);
```

行为：

- 输入长度小于 6 返回 `InvalidArgument`
- DLC 大于 8 返回 `InvalidArgument`
- 标准帧 ID 按 `id & 0x7FF`
- raw 格式固定 `[id little-endian 4][flags][dlc][payload]`

- [ ] **Step 4: 实现 CAN open 流程**

`open()` 顺序对齐原版：

1. `write32(XCAN_SRR_OFFSET, XCAN_SRR_SRST_MASK)`
2. 等待 100us
3. `write32(XCAN_SRR_OFFSET, 0)` 进入配置模式
4. 读取 `XCAN_SR_OFFSET`，确认 `XCAN_SR_CONFIG_MASK`
5. `write32(XCAN_MSR_OFFSET, loopback ? XCAN_MSR_LBACK_MASK : 0)`
6. 根据 `baud_rate` 配置 bit timing：
   - `1000000 -> BRPR=0, BTR=(3 << 7) | (6 << 4) | 15`
   - `500000 -> BRPR=1, BTR=(3 << 7) | (6 << 4) | 15`
   - `250000 -> BRPR=3, BTR=(3 << 7) | (6 << 4) | 15`
7. accept-all filter：
   - `AFR=0`
   - 等待 `SR.ACFBSY=0`
   - `AFMR1=0`
   - `AFIR1=0`
   - `AFR=XCAN_AFR_UAF1_MASK`
8. `write32(XCAN_SRR_OFFSET, XCAN_SRR_CEN_MASK)` 启用核心
9. `IER=TXOK|RXOK`
10. `ICR=TXOK|RXOK`

- [ ] **Step 5: 实现 CAN send**

发送标准帧：

1. 清 `ICR TXOK|RXOK`
2. 校验 `ide=false`、`dlc<=8`
3. 写 `TX_ID = (id & 0x7FF) << 21`
4. 写 `TX_DLC = dlc << 28`
5. 写 `TX_DW1` 为 payload[0..3] 大端字节序拼 32 位
6. 写 `TX_DW2` 为 payload[4..7] 大端字节序拼 32 位
7. 轮询 `ISR.TXOK`，最多 `1000 * 100us`
8. 成功后清 `ICR.TXOK`

- [ ] **Step 6: 实现 CAN receive**

接收流程：

1. 读 `ISR`
2. 无 `RXOK` 返回 `Result<size_t>{0}`
3. 读 `RX_ID/RX_DLC/RX_DW1/RX_DW2`
4. 解出 `CanFrame`
5. raw 输出为 `[id:4][flags][dlc][data]`
6. 清 `ICR.RXOK`

## Task 3: 实现 RS422 设备

**Files:**

- Create: `src/MB_DDF_HW/Device/Rs422Registers.h`
- Create: `src/MB_DDF_HW/Device/Rs422Device.h`
- Create: `src/MB_DDF_HW/Device/Rs422Device.cpp`

- [ ] **Step 1: 写入 RS422 寄存器常量**

迁移原版偏移：

```cpp
constexpr uint64_t RS422_RECV_BUF = 0x000;
constexpr uint64_t RS422_SEND_BUF = 0x100;
constexpr uint64_t RS422_UCR_REG  = 0x200;
constexpr uint64_t RS422_MCR_REG  = 0x201;
constexpr uint64_t RS422_BRSR_REG = 0x202;
constexpr uint64_t RS422_ICR_REG  = 0x203;
constexpr uint64_t RS422_THL_REG  = 0x204;
constexpr uint64_t RS422_THH_REG  = 0x205;
constexpr uint64_t RS422_RHL_REG  = 0x206;
constexpr uint64_t RS422_RHH_REG  = 0x207;
constexpr uint64_t RS422_LPB_REG  = 0x20C;
constexpr uint64_t RS422_INT_REG  = 0x20D;
constexpr uint64_t RS422_EVT_REG  = 0x210;
constexpr uint64_t RS422_CMD_REG  = 0x300;
constexpr uint64_t RS422_STU_REG  = 0x300;
constexpr uint64_t RS422_ERR_REG  = 0x304;
constexpr uint8_t RS422_STU_RX_READY_MASK = 0x01;
constexpr uint8_t RS422_STU_TX_READY_MASK = 0x02;
constexpr uint32_t RS422_CMD_TX = 0x81;
constexpr uint32_t RS422_CMD_RX = 0x82;
```

- [ ] **Step 2: 实现 `open()`**

1. 标记打开
2. 写 `ICR=1`
3. 调用 `configure(config_)`
4. 回读 `UCR/MCR/BRSR/ICR/LPB/INT`，失败返回 `IoError`

- [ ] **Step 3: 实现 `configure()`**

写寄存器顺序与原版一致：

1. `LPB`
2. `INT`
3. `EVT`
4. `UCR`
5. `MCR`
6. `BRSR`
7. `ICR`
8. `THL`
9. `THH`
10. `RHL`
11. `RHH`

- [ ] **Step 4: 实现 RS422 send**

1. 空数据返回成功 0
2. 长度截断到 255
3. 读 `STU_REG`，要求 `TX_READY`
4. `SEND_BUF + 0` 写入 `[len][data0][data1][data2]`
5. 从 `SEND_BUF + 4` 开始按原版 `idx = bram_offset + i - 1` 打包剩余数据
6. 写 `CMD_REG = CMD_TX`
7. 返回实际发送长度

- [ ] **Step 5: 实现 RS422 receive**

1. 读 `STU_REG` 和 `ERR_REG`
2. 无 `RX_READY` 返回 0
3. `ERR != 0` 时写 `ERR_REG=1` 并返回 `IoError`
4. 写 `CMD_REG = CMD_RX`
5. 读 `RECV_BUF` 首 word，低字节是真实长度，后 3 字节是数据
6. 继续从 `RECV_BUF + 4` 读取剩余数据
7. 返回拷贝到用户 buffer 的长度

- [ ] **Step 6: 实现 timeout receive**

优先使用 `transport.wait_event(timeout)`；如果事件不支持或超时，则每 100us 轮询 `STU_RX_READY_MASK`，直到 timeout。
