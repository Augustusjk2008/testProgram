# COM2 回显与完整硬件测试实施方案

## 目标

1. 将板端 COM2 原始回显、完整硬件测试服务和原 DDS/硬件 Demo 隔离为三个互斥编译画像。
2. `main.cpp` 仅保留日志初始化和编译期入口分派，原 Demo 编排迁移到独立文件。
3. PC 工具提供“回显模式”和“硬件测试模式”，覆盖全部产品协议测试项。
4. 修正协议 CSV 与 `codedesign.md`，确保帧长、字段类型、CRC、序号和 8E1 配置一致。
5. 本版不实现安全确认、状态恢复、自动重试、夹具检测、测试阈值或报告导出。

## 协议基线

- 控制口固定为板端 COM2：`/dev/xdma0`、偏移 `0x80000`、event 1。
- 串口配置固定为 `614400 / 8E1 / 无流控`。
- FPGA负责 `55 AA`、长度和 CRC；板端 C++ 只收发长度为 48 或 123 字节的数据段。
- PC CRC继续使用现有 CRC-16/XMODEM规则：初值 `0`、不反射、覆盖长度字节和数据段、低字节先发。
- PC与板端各自维护发送序号；每发送一帧递增，`0xFFFF` 后回到 `0`；响应不回显请求序号。
- PC一次只保留一个普通待响应请求，按指令类型和当前测试状态匹配响应；异步舵反馈单独路由。
- COM2作为控制口时，不执行 `link_id=3` 的 COM2总线自测；协议仍保留该编号。
- 测试模式只报告执行完成、执行失败和通信失败，不作硬件通过/失败判定。

## 实施步骤

### 1. 修订并校验产品协议 CSV

新增 `tools/generate_product_protocol.py`，同时承担 CSV 校验和生成板端协议描述头文件的职责。

校验规则：

- 列名必须符合合同。
- `len` 只能是 `48` 或 `123`。
- 完整帧长度必须等于 `len + 5`。
- `index`、`length` 和字段累计偏移必须一致。
- 多字节字段统一小端。
- CONST必须有默认值；RESERVED按零填充。
- 所有缺失且无其他来源的定标字段显式填写 `lsb=1`。

按以下差值调整 RESERVED，并同步重算后续 `index`：

| CSV | 数据段差值 |
|---|---:|
| `ad_read_request.csv` | RESERVED `+1` |
| `ad_read_response.csv` | RESERVED `-7` |
| `dh_control_request.csv` | RESERVED `-10` |
| `do_write_request.csv` | RESERVED `+1` |
| `do_write_response.csv` | RESERVED `-3` |
| `helm_start_request.csv` | RESERVED `-1` |
| `helm_start_response.csv` | RESERVED `-1` |
| `memperf_test_response.csv` | RESERVED `-4` |
| `power_switch_request.csv` | RESERVED `-1` |
| `power_switch_response.csv` | RESERVED `+1` |
| `spi_flash_test_response.csv` | RESERVED `+4` |

另行修正：

- `helm_feedback_response.csv` 的 `len` 从 `128` 改为 `123`，DH 64位定义保持原样。
- SPI Flash子类型改为 `0x02/0x02`。
- Bus Echo子类型改为 `0x03/0x02`。
- AD Read子类型改为 `0x04/0x03`。
- `helm_version` 固定为 `0x11`。
- `waveform`、`enable`、`timer_jitter.mode` 和八个抖动桶改为等宽 `U32`；测量值继续使用 F32。
- 三路电源值采用 `0=关闭、1=开启`。

生成文件放在构建目录，不提交机器路径或临时生成物；CMake依赖所有 CSV，CSV变化时自动重新生成。

### 4. 建立互斥构建画像

在 `CMakeLists.txt` 增加缓存项 `MB_DDF_APP_MODE`，取值仅允许：

- `ECHO`：默认画像，硬件层开启、DDS Adapter关闭。
- `HW_TEST`：完整测试服务，硬件层开启、DDS Adapter关闭。
- `DEMO`：原 DDS/硬件 Demo，保留现有 Adapter和全能力 Demo行为。

分别使用构建目录：

- `build/aarch64/echo/<Config>`
- `build/aarch64/hw_test/<Config>`
- `build/aarch64/demo/<Config>`
- `build/aarch64/tests/<Config>`

按画像条件编入源文件，避免回显和测试目标携带 Demo编排，也避免 CMake缓存粘连。

### 5. 实现 COM2 原始回显

`ComEchoRunner.cpp` 使用 `XdmaTransport + ComDevice`：

- 固定 COM2偏移 `0x80000`、event 1、Level中断和 8E1配置。
- 100 ms有界接收，收到有效 payload 后原样调用 `send()`。
- 保留 SIGINT/SIGTERM正常退出能力。
- 不保存或恢复原 COM配置，不执行 DDS、测试处理器或 Demo。
- 日志只输出到 `Logger.h`，不写入 COM2。

### 6. 实现板端产品协议服务

`ProductProtocol` 负责：

- 解析 FPGA提交的 48/123字节数据段。
- 校验版本、固定长度、type_group/sub_type和字段范围。
- 使用生成的字段偏移进行小端读写，不依赖 C++结构体内存布局。
- 板端统一维护发送序号。
- 普通执行错误返回原指令响应中的 `status/err_code`。
- 未知指令、版本或长度错误返回 `0xFF/0x00`；`orig_seq`保留请求序号。
- CRC错误由 FPGA处理，C++不重复实现。

`HardwareTestService` 使用单一 COM2接收循环；DH突发可同步发送，舵反馈使用一个独立工作线程，所有发送通过带锁的统一发送器串行化。

### 7. 覆盖全部硬件测试处理器

按 CSV 实现全部命令：

- 系统状态：参考 `UpgradeAndTest` 的 `SystemMonitor`、`MemoryMonitor`、`TemperatureReader`，补充 `/sys` CPU频率、PCIe状态和 `/proc/uptime`。
- 内存测试：参考 `MemoryTester` 和 `FileIOTester`；类型0～2执行 seed图样写入/校验，类型3～6执行读、写、拷贝和 NT store带宽测试。
- SPI Flash：使用 `/dev/spidev0.0` 和现有 `SpiFlashDevice` 执行固定测试区擦写读回；本画像不备份、不恢复。
- 总线：link 0/1使用 `192.168.1.29`、`192.168.7.29` 和固定 UDP端口；link 2/4/5映射 COM1/COM3/COM4；link 3返回 `CHANNEL_INVALID`；link 6使用 `/dev/spidev0.0`。
- DI/DO：使用 `DidoDevice`，仅 bit 0～15有效，其余回零。
- AD和电气健康：使用 AD7606/ADS1258快照，字段映射集中为常量表；读取源不可用时返回 `TASK_EXEC_FAILED`，不伪造测量值。
- 电源：按参考 IO映射执行三路 0/1控制并返回命令回读。
- DH：使用 `DhController`，bit 0～47有效，超出位保持0；允许直接触发并按请求次数回告。
- 舵控：参考 `APPMain.h` 的命令生成和反馈换算，使用当前 `PwmDevice + AD7606` API；START后持续发送10样本反馈帧，STOP停止线程。
- 定时器：参考 `SystemTimer/ChronoHelper` 算法，在当前工程内实现250 µs、250周期采样；桶为 U32，平均和最大抖动为 F32。
- 所有处理器不增加安全门、状态恢复、断链清理或自动重试。

### 9. 扩展 PC 协议与测试会话

新增：

- `test_pyqt/protocol_catalog.py`
- `test_pyqt/product_protocol.py`
- `test_pyqt/hardware_test_session.py`
- `test_pyqt/colored_log.py`

实现方式：

- `protocol_catalog.py` 运行时读取修订后的 CSV并校验 schema。
- `product_protocol.py` 只组装 B4至 CRC前的数据段，再交给现有 `SerialChannel` 添加物理帧，禁止双重 `55 AA`封装。
- PC发送序号独立递增；普通请求一次只允许一个在途。
- DH响应和舵反馈按会话状态接收，不按请求 seq匹配。
- 默认超时：普通2秒、总线60秒、内存120秒、SPI Flash180秒、DH按公式计算。
- 不自动重发。

执行全部的顺序固定为：系统状态、内存、SPI Flash、总线、DI、DO、电源、电气健康、AD、DH、舵控、定时器。

采用已确认默认参数；总线列表排除 link 3。

- 颜色固定为：TX蓝、RX青、完成绿、警告橙、错误红、普通信息深灰。
- 切换 PC模式只改变界面和解析逻辑，不自动切换板端程序。
