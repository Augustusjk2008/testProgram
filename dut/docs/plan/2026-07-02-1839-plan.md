**目标**

在 `MB_DDF_v2` 中把读取策略显式化，支持两种同步读取模式：

- `Blocking`：当前 wait/condvar 路径，支持超时或无限等待。
- `Polling`：No8RtBus nonblock 风格，不进入 `wait_for_message`，只检查是否有未读数据；没有数据立即返回 0，供实时线程忙轮询降低延迟。

核心原则：**不改共享内存布局，不改发布路径，不破坏现有 API 行为**。

**改动范围**

- [Subscriber.h](H:/Resources/RTLinux/Demos/MB_DDF_v2/src/MB_DDF/DDS/Subscriber.h)：新增读取策略枚举和显式读取 API。
- [Subscriber.cpp](H:/Resources/RTLinux/Demos/MB_DDF_v2/src/MB_DDF/DDS/Subscriber.cpp)：实现 `poll`、`read_blocking`、策略化读取。
- [DDSCore.h](H:/Resources/RTLinux/Demos/MB_DDF_v2/src/MB_DDF/DDS/DDSCore.h) / [DDSCore.cpp](H:/Resources/RTLinux/Demos/MB_DDF_v2/src/MB_DDF/DDS/DDSCore.cpp)：增加便捷入口。
- `tests/unit/test_publisher_subscriber.cpp`：补同步读取策略单元测试。
- `tests/hardware/test_hardware_performance.cpp`：补 64B 一对一 RT 轮询延迟测试，与现有 wait latency 对照。

**实施步骤**

1. 在 `Subscriber.h` 增加策略类型：
   ```cpp
   enum class ReadStrategy {
       Blocking,
       Polling
   };
   ```
   语义写清楚：`Polling` 不等待、不睡眠、不触发 `pthread_cond_wait`；`Blocking` 使用现有 `wait_for_message`。

2. 增加显式 API，保留旧接口：
   ```cpp
   size_t poll(void* data, size_t size, bool latest = true);
   int32_t read_blocking(void* data, size_t size, uint32_t timeout_us = 0, bool latest = true);
   int32_t read(void* data, size_t size, ReadStrategy strategy, uint32_t timeout_us = 0, bool latest = true);
   ```
   现有 `read(data, size, bool latest)` 保持非阻塞行为，内部转调 `poll`；现有 `read(data, size, uint32_t timeout_us)` 保持阻塞语义，内部转调 `read_blocking`。

3. 在 `Subscriber.cpp` 重构当前读取逻辑：
   - `poll`：先检查订阅状态和 callback 模式；外部端点走现有 `receive`；DDS 共享内存路径只调用 `get_unread_count` + `read_latest/read_next`，无数据直接返回 0。
   - `read_blocking`：先尝试 `poll`；如果无数据再调用 `wait_for_message`；被唤醒后再次 `poll`。
   - `read(strategy, ...)`：`Polling` 直接 `poll`，`Blocking` 走 `read_blocking`。
   - 明确避免把 `timeout_us == 0` 当成 nonblock，因为当前语义是无限等待。

4. 不修改 `RingBuffer` 的共享内存结构。
   现有 [RingBuffer.cpp](H:/Resources/RTLinux/Demos/MB_DDF_v2/src/MB_DDF/DDS/RingBuffer.cpp:241) 已有 `get_unread_count`，现有 [RingBuffer.cpp](H:/Resources/RTLinux/Demos/MB_DDF_v2/src/MB_DDF/DDS/RingBuffer.cpp:259) 已有 `read_latest`，足够实现 nonblock 轮询。

5. 在 `DDSCore` 增加便捷入口：
   ```cpp
   size_t data_poll(std::shared_ptr<Subscriber> subscriber, void* data, size_t size, bool latest = true);
   int32_t data_read(std::shared_ptr<Subscriber> subscriber, void* data, size_t size,
                     ReadStrategy strategy, uint32_t timeout_us = 0, bool latest = true);
   ```
   旧 `data_read(subscriber, data, size)` 保持原样，继续走当前非阻塞 latest 读取。

6. 单元测试补充：
   - `SubscriberPollReturnsImmediatelyWhenEmpty`：无数据时 `poll` 返回 0，耗时应远小于阻塞超时。
   - `SubscriberPollReadsPublishedMessage`：发布后 `poll` 可读到数据。
   - `SubscriberReadBlockingStillWaits`：阻塞接口仍能等待后续发布。
   - `SubscriberStrategyPollingDoesNotIncreaseWaiterCount`：轮询读取不应让 `waiting_subscribers` 增加。
   - `SubscriberStrategyBlockingUsesWaitPath`：阻塞读取期间 `waiting_subscribers` 可观测到增加。

7. 硬件性能测试补充：
   - 在现有 64B RT wait latency 测试旁边新增 `RealtimePinnedOneToOnePollLatency64BOnTarget`。
   - 条件保持一致：64B、一对一、发送/接收线程 `SCHED_FIFO` 最高优先级、CPU 环境变量继续支持 `MB_DDF_RT_LATENCY_PRODUCER_CPU` 和 `MB_DDF_RT_LATENCY_CONSUMER_CPU`。
   - 接收线程进入固定轮询循环：
     ```cpp
     while (running) {
         int32_t n = reader->read(buffer, sizeof(buffer), ReadStrategy::Polling, 0, true);
         if (n > 0) record_latency();
         cpu_relax();
     }
     ```
   - AArch64 下 `cpu_relax()` 用 `asm volatile("yield" ::: "memory")`，避免 `sleep` 或 `sched_yield` 破坏低延迟测试。
   - 输出指标沿用现有格式，新增 `poll_latency_rt_pinned`，便于和 `wait_latency_rt_pinned` 横向比较。

8. 文档和注释：
   - 在 `Subscriber.h` 中明确说明三种入口差异：`poll` 非阻塞、`read_blocking` 阻塞、旧 `read(timeout_us)` 中 `0` 表示无限等待。
   - 在性能测试输出中标明 polling 会占用 CPU，只适用于专用实时核或短窗口低延迟场景。

**预期结果**

- API 层可以明确选择阻塞或轮询，不再依赖容易混淆的 `timeout_us == 0`。
- Polling 路径不进入 `pthread_cond_wait/broadcast`，理论上应低于当前 wait latency。
- 在 CPU5/CPU6、RT 优先级、一对一、64B 数据下，poll latency 应接近旧 MB_DDF futex 或更低的平均值，但代价是接收线程持续占用一个 CPU 核。
