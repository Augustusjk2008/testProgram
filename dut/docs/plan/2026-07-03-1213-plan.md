# Hardware Layer Split Implementation Plan

> **Execution note:** This plan should be executable either inline in the current session or by a delegated worker. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `MB_DDF_v2` 中把硬件接口作为独立层建设：先写设计文档，再在 `src\MB_DDF` 平级目录实现硬件层的 `Os` 层和 `Transport` 层。

**Architecture:** DDS 继续保持 DDS-only，不把硬件实现放回 `src\MB_DDF`。新增硬件层放在 `H:\Resources\RTLinux\Demos\MB_DDF_v2\src\MB_DDF_HW`，命名空间使用 `MB_DDF::HW`。本阶段只实现底层 OS 资源封装和 Transport 抽象/实现，不实现 CAN、RS422 等具体 Device 层。

**Tech Stack:** C++20、AArch64 交叉编译、CMake、PowerShell 构建脚本、Linux fd/mmap/poll/eventfd/ioctl。

---

1. 写一份硬件层层次化设计文档，说明模块边界、目录结构、接口设计、错误模型、DDS 集成原则，但不写具体设备实现。

3. 默认 DDS-only 构建和测试不受影响，硬件层通过显式 CMake 开关启用。

```markdown
# Hardware Layer Architecture

## 目标

硬件层从 DDS 中独立出来，作为独立 C++ 模块提供 OS 资源封装、Transport 能力、Device 能力和可选 DDS Adapter。
DDS Core 不依赖硬件层，硬件层不依赖 DDS Core。

## 依赖方向

DDS Core <- Hardware-DDS Adapter -> Hardware Layer

Hardware Layer 内部依赖方向：

Core <- Os <- Transport <- Device <- Factory

## 目录结构

src/MB_DDF_HW/
  Core/
  Os/
  Transport/
  Device/
  Factory/

## Core 层

定义 Status、Result、BufferView、MutableBufferView、Timeout。
Core 层不依赖 Linux 系统头，尽量保持可单测。

## Os 层

封装 Linux 资源生命周期：

- Fd：唯一所有权 fd，析构 close。
- MmapRegion：唯一所有权 mmap 区域，析构 munmap。
- Poll：poll fd 等待工具函数。

## Transport 层

Transport 只表达底层访问能力，不表达 CAN、RS422 等设备协议。

ITransport 职责：

- open/close
- read/write register
- optional dma read/write
- optional event fd
- wait event

RegisterAccessor 职责：

- typed read8/read16/read32
- typed write8/write16/write32
- offset/length/alignment 检查
- 小端转换

XdmaTransport 职责：

- 打开 /dev/xdmaN_user
- 可选打开 h2c/c2h DMA channel
- 可选打开 events fd
- mmap user BAR
- 实现寄存器访问和事件等待

NullTransport 职责：

- 用于单元测试
- 内存模拟寄存器空间
- 不访问真实硬件

## Device 层

本阶段不实现。未来 Device 层负责 CAN、RS422、DDR、GPIO 等设备语义。
Device 层只能依赖 Transport，不直接管理 fd/mmap。

## Factory 层

本阶段不实现。未来 Factory 层接收强类型配置，返回 Device Endpoint。
旧 create(string, void*) 不作为新硬件层主接口。

## DDS 集成原则

DDS 只保留 ExternalEndpoint 抽象。
后续新增 Hardware-DDS Adapter，Adapter 同时依赖 DDS 和 HW。
禁止 DDS Core 直接 include MB_DDF_HW 头文件。

## 错误模型

使用 Result<T> 返回成功值或 Status。
Status 包含 code、errno_value、message。
构造函数不做可能失败的系统调用；open() 返回 Result/Status。

## 本阶段交付

- 文档
- Core 基础类型
- Os 层
- Transport 接口
- NullTransport
- XdmaTransport 基础实现
- 单元测试
```

```cpp
#pragma once

#include <cerrno>
#include <string>

namespace MB_DDF::HW {

enum class StatusCode {
    Ok = 0,
    InvalidArgument,
    NotOpen,
    OpenFailed,
    MapFailed,
    IoError,
    Timeout,
    Unsupported,
};

struct Status {
    StatusCode code{StatusCode::Ok};
    int errno_value{0};
    std::string message{};

    static Status ok() { return {}; }

    static Status error(StatusCode c, int err, std::string msg) {
        return Status{c, err, std::move(msg)};
    }

    bool is_ok() const { return code == StatusCode::Ok; }
    explicit operator bool() const { return is_ok(); }
};

} // namespace MB_DDF::HW
```

- [ ] **Step 3: 定义 `Result<T>`**

`Result.h` 定义：

```cpp
#pragma once

#include "MB_DDF_HW/Core/Status.h"

#include <utility>

namespace MB_DDF::HW {

template <typename T>
class Result {
public:
    Result(T value) : ok_(true), value_(std::move(value)), status_(Status::ok()) {}
    Result(Status status) : ok_(false), value_(), status_(std::move(status)) {}

    bool is_ok() const { return ok_; }
    explicit operator bool() const { return ok_; }

    T& value() { return value_; }
    const T& value() const { return value_; }

    const Status& status() const { return status_; }

private:
    bool ok_{false};
    T value_{};
    Status status_{};
};

template <>
class Result<void> {
public:
    Result() : status_(Status::ok()) {}
    Result(Status status) : status_(std::move(status)) {}

    bool is_ok() const { return status_.is_ok(); }
    explicit operator bool() const { return is_ok(); }

    const Status& status() const { return status_; }

private:
    Status status_{};
};

} // namespace MB_DDF::HW
```

- [ ] **Step 2: 实现 `Fd`**

`Fd` 要求：

- 禁止拷贝。
- 支持移动。
- 析构自动 `close()`。
- `valid()` 判断 `fd >= 0`。
- `release()` 交出所有权。
- `set_nonblock()` 返回 `Status`。

- [ ] **Step 3: 实现 `MmapRegion`**

`MmapRegion` 要求：

- 禁止拷贝。
- 支持移动。
- 析构自动 `munmap()`。
- `map(int fd, size_t length, off_t offset)` 返回 `Result<MmapRegion>`。
- `data()` 返回 `void*`。
- `size()` 返回映射长度。
- 映射失败返回 `StatusCode::MapFailed` 和 `errno`。

- [ ] **Step 4: 实现 `Poll`**

`Poll` 要求：

- 提供 `Result<int> wait_readable(int fd, Timeout timeout)`。
- `timeout.infinite` 转成 `poll(..., -1)`。
- `timeout.microseconds` 转成毫秒，非零但不足 1ms 时按 1ms。
- 返回值：
  - `1` 表示可读。
  - `0` 表示超时。
  - 错误返回 `StatusCode::IoError`。

```cpp
#pragma once

#include "MB_DDF_HW/Core/Buffer.h"
#include "MB_DDF_HW/Core/Result.h"
#include "MB_DDF_HW/Core/Timeout.h"
#include "MB_DDF_HW/Transport/RegisterAccessor.h"

#include <cstddef>
#include <cstdint>

namespace MB_DDF::HW {

class ITransport : public RegisterAccessor {
public:
    virtual ~ITransport() = default;

    virtual Result<void> open() = 0;
    virtual void close() noexcept = 0;
    virtual bool is_open() const = 0;

    virtual Result<int> event_fd() const {
        return Status::error(StatusCode::Unsupported, 0, "event fd is not supported");
    }

    virtual Result<int> wait_event(Timeout timeout) = 0;

    virtual Result<size_t> dma_write(int channel, BufferView data, uint64_t device_offset) {
        (void)channel;
        (void)data;
        (void)device_offset;
        return Status::error(StatusCode::Unsupported, 0, "dma_write is not supported");
    }

    virtual Result<size_t> dma_read(int channel, MutableBufferView buffer, uint64_t device_offset) {
        (void)channel;
        (void)buffer;
        (void)device_offset;
        return Status::error(StatusCode::Unsupported, 0, "dma_read is not supported");
    }
};

} // namespace MB_DDF::HW
```

## Task 6: 实现 XdmaTransport

**Files:**

- Create: `src/MB_DDF_HW/Transport/XdmaTransport.h`
- Create: `src/MB_DDF_HW/Transport/XdmaTransport.cpp`

- [ ] **Step 1: 定义 `XdmaTransport` 类**

要求：

- 构造函数接收 `XdmaConfig`。
- 持有：
  - `Os::Fd user_fd_`
  - `Os::Fd h2c_fd_`
  - `Os::Fd c2h_fd_`
  - `Os::Fd event_fd_`
  - `Os::MmapRegion user_map_`
- `open()` 打开 `device_path + "_user"`，并 mmap user BAR。
- 如果 `h2c_channel >= 0`，打开 `device_path + "_h2c_N"`。
- 如果 `c2h_channel >= 0`，打开 `device_path + "_c2h_N"`。
- 如果 `event_number >= 0`，打开 `device_path + "_events_N"`。
- 至少 user mmap 成功才认为 open 成功。
- `close()` 释放所有资源。

- [ ] **Step 2: 实现寄存器访问**

要求：

- `read8/write8` 不要求对齐。
- `read16/write16` 要求 2 字节对齐。
- `read32/write32` 要求 4 字节对齐。
- 所有访问都检查 `offset + size <= map_length`。
- 使用小端语义。
- 失败返回 `StatusCode::InvalidArgument` 或 `StatusCode::NotOpen`。

- [ ] **Step 3: 实现事件等待**

要求：

- `event_fd()` 返回打开的 event fd。
- 没有 event fd 时返回 `Unsupported`。
- `wait_event(timeout)` 通过 `Os::Poll::wait_readable()` 等待。
- timeout 返回 `Result<int>{0}`。
- 可读返回 `Result<int>{1}`。

- [ ] **Step 4: 实现同步 DMA**

要求：

- `dma_write()` 使用 `pwrite()` 写 h2c fd。
- `dma_read()` 使用 `pread()` 读 c2h fd。
- channel 参数必须匹配配置 channel；不匹配返回 `InvalidArgument`。
- fd 未打开返回 `Unsupported`。
- 系统调用失败返回 `IoError` 和 `errno`。
