# XDMA 硬件设备层实施计划

## 一、目标

在 `src/MB_DDF_HW` 中完整接入当前 6 类、共 9 个 XDMA 硬件实例：

| 设备 | 实例数 | XDMA 映射基址 | 映射长度 | Event |
|---|---:|---:|---:|---:|
| `PWM_ctrl` | 1 | `0x00000` | `0x10000` | 无 |
| `AD7606_HELM` | 1 | `0x10000` | `0x10000` | 无 |
| `ADS1258` | 1 | `0x20000` | `0x10000` | 无 |
| `DH_ctrl` | 1 | `0x30000` | `0x10000` | 无 |
| `COM` 第 1 路 | 1 | `0x40000` | `0x40000` | 0 |
| `COM` 第 2 路 | 1 | `0x80000` | `0x40000` | 1 |
| `COM` 第 3 路 | 1 | `0xC0000` | `0x40000` | 2 |
| `COM` 第 4 路 | 1 | `0x100000` | `0x40000` | 3 |
| `DIDO_ctrl` | 1 | `0x140000` | `0x10000` | 无 |

总体目标：

1. 每个设备通过独立 `XdmaTransport` 打开和映射同一个 `/dev/xdma0_user`。
2. Device 非拥有地引用 `ITransport`，调用方负责 Transport 生命周期。
3. 设备层提供强类型高级 API，不向业务暴露寄存器操作序列。
4. 打开 Transport 时不写任何业务寄存器。
5. 每个设备提供 `check_communication()`。
6. 当前全部通过 MMIO 和片上 RAM 操作，不使用 H2C/C2H DMA。
7. 保留未来新增 IP、实例和 H2C/C2H DMA Transport 的扩展边界。
8. 不增加统一 Hardware Manager。
9. 不修改 DDS Core 的既有行为。
10. 提供独立的 `MB_DDF_HW_DDS_Adapter`，兼容 `ExternalEndpoint`。
11. 允许多线程、多进程访问，但硬件层和 Adapter **不增加任何互斥机制**。
12. 不采用寄存器状态轮询；ADC 立即读取当前值，COM 只通过 XDMA event fd 等待接收事件。
13. 所有测试二进制均使用 AArch64 交叉编译并在目标板执行，主机不运行测试二进制。

## 二、架构设计

### 2.1 分层结构

```text
Core
├── Status / Result
├── Buffer / Timeout
└── 设备公共值类型

Os
├── Fd
├── MmapRegion
└── Epoll

Transport
├── RegisterAccessor
├── ITransport
├── NullTransport
└── XdmaTransport

Device
├── PwmDevice
├── Ad7606Device
├── Ads1258Device
├── DhController
├── DidoDevice
└── ComDevice

DdsAdapter
├── ExternalEndpointAdapter
├── CallbackExternalEndpoint
└── ComExternalEndpoint
```

依赖方向：

```text
Core <- Os <- Transport <- Device
                         ^
                         |
                    DdsAdapter
                         |
                         v
                DDS ExternalEndpoint
```

`MB_DDF_HW` 不包含或依赖 DDS 头文件。

`MB_DDF_HW_DDS_Adapter` 单独依赖：

- `MB_DDF_HW`
- `MB_DDF/DDS/ExternalEndpoint.h`

---

### 2.2 Transport 所有权

调用方式：

```cpp
MB_DDF::HW::XdmaTransport transport(config);

auto opened = transport.open();
if (!opened) {
    // 处理错误
}

MB_DDF::HW::PwmDevice pwm(transport);
```

约束：

- Device 构造函数不打开硬件。
- Device 构造函数不写寄存器。
- Device 保存 `ITransport&`。
- Transport 必须比 Device 存活更久。
- Device 不调用 `transport.close()`。
- 每个实际设备实例使用独立 Transport。
- 不共享 fd、映射对象或事件对象。
- 不在 Transport 或 Device 内添加锁。

---

### 2.3 地址规则

非 COM 设备：

```text
局部字节偏移 = Excel 表内地址 × 4
实际 XDMA 地址 = XdmaConfig.user_offset + 局部字节偏移
```

COM：

```text
局部字节偏移 = Excel 表内地址
实际 XDMA 地址 = COM 实例基址 + 局部字节偏移
```

Device 代码只使用局部偏移，实例基址全部由 `XdmaConfig.user_offset` 处理。

---

### 3.3 XdmaTransport

修改：

```text
src/MB_DDF_HW/Transport/XdmaTransport.h
src/MB_DDF_HW/Transport/XdmaTransport.cpp
src/MB_DDF_HW/Transport/TransportConfig.h
```

#### MMIO 访问修正

将现有拆字节实现替换为原生宽度访问：

```text
read8/write8   -> volatile uint8_t
read16/write16 -> volatile uint16_t
read32/write32 -> volatile uint32_t
```

要求：

- 小端访问。
- 保留对齐检查。
- 保留映射边界检查。
- 16/32 位访问不拆成多个字节操作。
- 写前使用 release fence。
- 读后使用 acquire fence。
- 不增加 mutex。
- 不假设未在 Excel 中声明的读取清除或写一清零语义。

#### Event 初始化

当 `event_number >= 0`：

1. 打开 `/dev/xdma0_events_N`。
2. 使用 `O_RDONLY | O_NONBLOCK`。
3. 创建持久化 epoll fd。
4. 将 event fd 注册为 `EPOLLIN`。

#### `wait_event()`

语义：

```cpp
Result<int> wait_event(Timeout timeout);
```

实现：

1. `Timeout::poll()`：
   - 调用一次 `epoll_wait(..., timeout=0)`。
   - 无事件返回 `0`。
2. `Timeout::after_us(x)`：
   - 通过 epoll 等待。
   - 不查询设备状态寄存器。
3. `Timeout::forever()`：
   - epoll 永久等待。
4. 事件就绪后：
   - 从 XDMA event fd 读取一个 32 位事件计数。
   - 读取行为负责消费/清除驱动侧 event。
   - 返回事件计数，至少返回正值。
5. `EAGAIN` 作为竞争导致的无事件处理。
6. 其他 read/epoll 错误返回 `IoError`。

#### DMA 扩展性

保留现有：

```cpp
dma_write()
dma_read()
```

本次设备实现不调用它们，但不删除、不弱化其接口。

## 六、PWM_ctrl

新增：

```text
src/MB_DDF_HW/Device/PwmDevice.h
src/MB_DDF_HW/Device/PwmDevice.cpp
```

### 6.1 类型

```cpp
enum class PwmWaveform {
    Sawtooth,
    Triangle,
};

struct PwmRawOutputs {
    std::array<uint32_t, 4> duty;
    uint8_t direction_mask;
    uint8_t enable_mask;
};

struct PwmNormalizedOutputs {
    std::array<double, 4> value;
    uint8_t enable_mask;
};

struct PwmConfig {
    uint32_t carrier_frequency_value;
    uint32_t peak_value;
    PwmWaveform waveform;
};
```

无符号模式作为正常业务模式。

归一化接口约定：

```text
value ∈ [-1.0, 1.0]
direction = value >= 0
duty = abs(value) × peak_value
```

超出范围返回 `InvalidArgument`，不静默裁剪。

### 6.2 API

```cpp
Result<void> configure(const PwmConfig&);
Result<void> set_duty_mode_unsigned();
Result<void> set_update_enabled(bool);
Result<void> apply_outputs(const PwmRawOutputs&);
Result<void> apply_normalized_outputs(const PwmNormalizedOutputs&);
Result<PwmState> read_state() const;
Result<uint32_t> read_peak_value() const;
```

### 6.3 输出顺序

`apply_outputs()`：

1. 校验 4 路 duty 均不超过当前波峰值。
2. 读取当前 PWM enable mask。
3. 写 4 路方向寄存器。
4. 写 4 路占空比寄存器。
5. 若当前 enable mask 与请求值不同，仅写一次 PWM 使能寄存器。
6. 不自动切换占空比更新使能寄存器。
7. 不使用缓存判断 enable mask，避免跨进程状态陈旧。

PWM 使能写值按 Excel 的 4 位 nibble 编码：

- 使能：`0xA`
- 禁用：`0xF`

- 寄存器 `0x71` 配置底层时间单位计数。
- 原始 API 以 ticks 操作。
- 毫秒 API 要求：
  ```text
  milliseconds % unit_milliseconds == 0
  ```
- 不可整除时返回 `InvalidArgument`，不静默取整。
- 默认业务配置可使用 `unit_milliseconds = 1`，但不会自动写入。

### 10.4 点火

单路：

- 校验通道 `0～47`。
- 根据 Excel 中每通道的命令值写对应指令寄存器。
- 不等待回告。

多路：

1. 校验所有通道。
2. 去除重复通道，保持首次出现顺序。
3. 每次最多将 4 个通道编码到 `0x73`。
4. 不足 4 路的位置填写 `0xFF`。
5. 写 `0x73`。
6. 写 `0x74` 触发当前批次。
7. 对后续通道重复以上过程，因此可点火超过 4 路。
8. 不等待回告。

安全约束：

- 不增加 magic、token 或二次确认。
- 板端 smoke test 完全禁止点火写操作。
- 点火写流程只在 Fake/Recording Transport 测试中验证。

最大 payload：

```text
65536 字节
```

### 11.3 发送流程

1. 校验 Transport 已打开。
2. 校验 `data.size <= 65536`。
3. 读取发送忙状态。
4. 忙时返回 `StatusCode::Busy`，不轮询等待。
5. 按 32 位小端写入发送 RAM `0x10000`。
6. 每次地址增加 4。
7. 最后不足 4 字节补零。
8. payload 中不加入帧长。
9. 将本次发送长度写入发送长度寄存器 `0x2001C`。
10. 通过 `0x30000` 的发送使能语义触发发送。
11. 不等待发送完成。

### 11.4 接收流程

1. 调用 `transport.wait_event(timeout)`。
2. 无事件：
   - 非阻塞或超时返回 `0`。
3. event 到达后由 Transport 读取 XDMA event fd 的 32 位计数，消费驱动事件。
4. 立即读取 COM 错误状态寄存器 `0x30004`。
5. 若存在任何接收错误：
   - 写 `0xCCCC` 清除错误状态。
   - 按当前中断模式执行必要的接收重置/中断清除。
   - 返回 `ProtocolError`。
   - 不向调用方交付 payload。
6. 读取接收帧数据长度配置。
7. 如果接收帧长度字段宽度为 0：
   - 从接收字节数量寄存器 `0x3000C` 获取长度。
   - 接收 RAM 从第一个 payload 字节开始。
8. 如果接收帧长度字段宽度为 1 或 2：
   - 从接收 RAM 起始位置读取帧长。
   - payload 紧随长度字段。
9. 校验长度不超过 65536。
10. 若调用方容量不足：
    - 返回 `BufferTooSmall`。
    - 不做部分帧交付。
11. 按 32 位小端读取接收 RAM。
12. 去掉 RAM 中的长度字段，只返回 payload。
13. 高电平中断模式下，通过 `0x30000` 的接收使能/清除语义拉低中断并重新接收。
14. 高脉冲模式不执行多余的硬件状态轮询。

### 11.5 Timeout

- `Timeout::poll()`：一次非阻塞 epoll 检查。
- `Timeout::after_us()`：epoll 等待指定时间。
- `Timeout::forever()`：永久等待 event。
- 不读取 COM 状态寄存器进行等待。
- 不实现睡眠轮询。

### 12.1 硬件层 Endpoint

```cpp
class IByteEndpoint {
public:
```


### 12.4 非 COM Callback Adapter

构造时由调用方传入：

```cpp
using SendCallback =
    std::function<Result<size_t>(BufferView)>;

using ReceiveCallback =
    std::function<Result<size_t>(
        MutableBufferView,
        Timeout)>;

using MtuCallback =
    std::function<size_t()>;
```

用户回调自行决定：

- DDS payload 格式。
- 如何解析 payload。
- 调用哪个 Device 高级 API。
- 如何把设备快照编码为 DDS payload。
- 是否忽略 timeout。

```text

receive 成功且有数据   -> 正字节数
receive 无数据/超时    -> 0
receive 硬件/协议错误  -> -1
```

`control()` 默认返回 `-1`。

不增加 mutex。

## 十八、完成标准
