# DDS Gateway 独立模块实施方案

**目标:** 在当前单域共享内存 DDS 之上新增独立 Gateway 模块，实现 1-2-3 这类非全互联域拓扑的跨域泛洪转发：监控本地域全部普通 topic，排除 gateway 内部 topic，支持多个 endpoint，收到远端消息后本地发布并转发到其它 endpoint。

**改动范围:** 不改业务 DDS 使用方式；不引入 `type_hash`；不做高频/危险 topic 策略；不修改 `MessageHeader` 布局。允许给 `DDSCore/Subscriber/Publisher/RingBuffer` 增加窄内部接口，用于枚举 topic、带序列号观察消息、发布后返回本地序列号。

**模块位置:** 做在本项目内的独立模块，建议目录为 `src/MB_DDF/DDS/Gateway/`，不塞进 `DDSCore` 主逻辑。

---

## 1. 目标行为

- Gateway 启动后按配置周期扫描本地域可订阅 topic。
- 默认订阅所有 topic，但排除 `gateway://` 前缀的内部 topic。
- 本地域普通 topic 有新消息时，封装为 gateway envelope，发送到所有已启用 endpoint。
- endpoint 收到远端 envelope 后：
  - 先做格式校验和去重。
  - 在本地域同名 topic 发布 payload。
  - 记录本次本地注入产生的本地序列号，避免本地 monitor 再把它当成本地新消息转发。
  - 若 TTL 仍大于 1，则转发给除入口 endpoint 以外的其它 endpoint。
- 对 1-2-3 拓扑：
  - 1 发出的消息经 2 转发到 3。
  - 3 发出的消息经 2 转发到 1。
  - 2 发出的消息同时发到 1 和 3。
  - 1 和 3 不需要直连。

## 3. 核心接口设计

### 3.1 Gateway 配置

```cpp
struct DomainGatewayConfig {
    uint32_t domain_id{0};
    uint64_t gateway_id{0};
    uint32_t topic_scan_period_ms{1000};
    uint8_t default_ttl{16};
    std::string internal_topic_prefix{"gateway://"};
};
```

`gateway_id` 可配置；若为 0，启动时生成随机 ID。测试中固定设置。

### 3.2 Endpoint 配置

```cpp
struct GatewayEndpointConfig {
    std::string name;
    ExternalEndpointRef endpoint;
    bool enabled{true};
};
```

一个 Gateway 可 `add_endpoint()` 多次。

### 3.3 跨域 Envelope

不放 `type_hash`。topic 用字符串。

```cpp
struct GatewayEnvelopeHeader {
    uint32_t magic;              // 例如 0x47445732, "GDW2"
    uint16_t version;            // 1
    uint16_t header_size;
    uint32_t flags;
    uint32_t origin_domain_id;
    uint32_t sender_domain_id;
    uint64_t origin_gateway_id;
    uint64_t message_id;
    uint8_t ttl;
    uint8_t reserved[7];
    uint16_t topic_name_size;
    uint32_t payload_size;
    uint32_t payload_crc32;
};
```

序列化格式：

```text
GatewayEnvelopeHeader + topic_name bytes + payload bytes
```

去重键：

```text
(origin_domain_id, origin_gateway_id, message_id)
```

转发时：
- `origin_domain_id` 不变。
- `origin_gateway_id` 不变。
- `message_id` 不变。
- `sender_domain_id` 改为当前域。
- `ttl` 减 1。

## 4. DDS 内部接口补充

为了避免远端注入消息被本地 monitor 重新广播，需要本地消息序列号。

新增内部结构：

```cpp
struct LocalTopicInfo {
    uint32_t topic_id;
    std::string topic_name;
    size_t ring_buffer_size;
};

struct LocalMessageView {
    std::string topic_name;
    uint64_t sequence;
    uint64_t timestamp;
    const void* data;
    size_t size;
};

using LocalMessageCallback = std::function<void(const LocalMessageView&)>;
```

在 `DDSCore` 增加：
- `std::vector<LocalTopicInfo> list_topics() const;`
- `std::shared_ptr<Subscriber> create_observer(const std::string& topic_name, const LocalMessageCallback& callback);`
- `uint64_t publish_and_get_sequence(const std::string& topic_name, const void* data, size_t size);`

实现方式：
- `list_topics()` 代理 `TopicRegistry::get_all_topics()`。
- `create_observer()` 仍使用普通 `Subscriber`，但让 `Subscriber` 支持携带 `MessageHeader.sequence` 的观察回调。
- `publish_and_get_sequence()` 通过 `Publisher/RingBuffer` 返回提交后的本地 sequence，失败返回 0。
- 现有 `create_publisher/create_subscriber/write/read` 行为保持不变。

## 5. GatewayLocalBus 抽象

`DomainGateway` 不直接依赖 `DDSCore`，而依赖接口，便于单元测试模拟 1-2-3 拓扑。

```cpp
class GatewayLocalBus {
public:
    virtual ~GatewayLocalBus() = default;
    virtual std::vector<LocalTopicInfo> list_topics() = 0;
    virtual bool subscribe_topic(const std::string& topic_name, LocalMessageCallback callback) = 0;
    virtual uint64_t publish_topic(const std::string& topic_name, const void* data, size_t size) = 0;
};
```

`DdsGatewayLocalBus` 用 `DDSCore::instance()` 实现该接口。

## 6. DomainGateway 内部状态

```cpp
class DomainGateway {
public:
    explicit DomainGateway(DomainGatewayConfig config,
                           std::shared_ptr<GatewayLocalBus> local_bus);

    bool add_endpoint(const GatewayEndpointConfig& endpoint);
    bool start();
    void stop();

    void scan_topics_once();       // 测试和周期线程共用
    void poll_endpoint_once(size_t endpoint_index); // 测试辅助

private:
    // monitored_topics_: topic_name -> subscription held by local bus
    // suppressed_local_sequences_: (topic_name, local_sequence)
    // seen_remote_messages_: duplicate window
    // endpoints_: endpoint list + receive thread
};
```

线程模型：
- 一个 topic scan 线程，按 `topic_scan_period_ms` 调用 `scan_topics_once()`。
- 每个 endpoint 一个 receive 线程。
- 发送路径用 endpoint 级 mutex，避免多线程同时调用同一个 `ExternalEndpoint::send()`。

## 7. 实施步骤

1. 新增 `GatewayEnvelope` 序列化/反序列化。
   - 校验 magic、version、header_size、topic 长度、payload 长度、CRC。
   - 序列化失败时返回空 buffer 或 false。

2. 新增 `GatewayLocalBus` 接口和 `DdsGatewayLocalBus` 适配器。
   - 先只定义接口，测试用 fake bus。
   - 后接入 `DDSCore` 新增内部接口。

3. 扩展 `RingBuffer` 发布路径返回 sequence。
   - 保留原 `publish_message(data, size)`。
   - 新增 overload：`publish_message(data, size, uint64_t* out_sequence)`。
   - `commit` 成功后写出本次 `seq`。

4. 扩展 `Publisher`。
   - 保留 `bool publish/write`。
   - 新增 `uint64_t publish_and_get_sequence(const void* data, size_t size)`。

5. 扩展 `Subscriber`。
   - 保留原 `MessageCallback`。
   - 新增观察回调，用于返回 `topic_name + sequence + timestamp + payload`。
   - worker loop 读到 `Message* msg` 后构造 `LocalMessageView`。

6. 扩展 `DDSCore`。
   - 添加 `list_topics()`。
   - 添加 `create_observer()`。
   - 添加 `publish_and_get_sequence()`。

7. 实现 `DomainGateway::scan_topics_once()`。
   - 调用 local bus `list_topics()`。
   - 跳过空 topic、已订阅 topic、`gateway://` 前缀 topic。
   - 对新 topic 调用 `subscribe_topic()`。
   - 回调进入 `on_local_message()`。

8. 实现本地消息转发。
   - 若 `(topic, sequence)` 在 `suppressed_local_sequences_` 中，删除该 key 并返回。
   - 否则生成 envelope：
     - `origin_domain_id = config.domain_id`
     - `sender_domain_id = config.domain_id`
     - `origin_gateway_id = config.gateway_id`
     - `message_id = ++local_message_counter`
     - `ttl = default_ttl`
   - 发送到所有 enabled endpoint。

9. 实现远端消息接收。
   - 从 endpoint receive buffer 反序列化 envelope。
   - 若重复 key 已存在，丢弃。
   - 若 `origin_domain_id == config.domain_id`，丢弃，防止绕路回到源域。
   - 调用 local bus `publish_topic(topic, payload)`，拿到本地 sequence。
   - 记录 `(topic, local_sequence)` 到 `suppressed_local_sequences_`。
   - 若 `ttl > 1`，转发到除入口 endpoint 外的其它 enabled endpoint。

10. 增加去重窗口清理。
    - `seen_remote_messages_` 限制最大条目，例如 4096。
    - `suppressed_local_sequences_` 限制最大条目，例如 4096。
    - 超限时删除最旧条目。

11. 接入 CMake。
    - 将 Gateway `.cpp` 加入 `DDS_CORE_SOURCES`。
    - 将 Gateway `.h` 加入 `DDS_PUBLIC_HEADERS`。
    - 将 gateway 测试加入 `TEST_SOURCES`。

## 8. 验证步骤

1. Envelope 单元测试：
   - 正常 round-trip。
   - bad magic 反序列化失败。
   - bad version 失败。
   - 截断 header 失败。
   - 截断 payload 失败。
   - CRC 错误失败。

2. Gateway 单元测试：
   - `scan_topics_once()` 订阅普通 topic。
   - `gateway://status` 这类内部 topic 不订阅。
   - 本地 topic 消息发送到所有 endpoint。
   - 远端消息进入本地 bus 后转发到其它 endpoint，不转发回入口 endpoint。
   - 远端注入产生的本地 sequence 被 suppress，不会再次广播。
   - 重复 `(origin_domain, gateway_id, message_id)` 被丢弃。
   - 1-2-3 fake topology 中，1 的消息能到 3，3 的消息能到 1，1 和 3 不需要直连。

3. 构建验证：
   - `.\tests\test-dds-only.ps1 -BuildOnly`

   - 预期：新增 gateway 测试全部通过。

5. 回归测试：

## 9. 重要约束

- 不引入 topic 类型匹配和 `type_hash`。
- 不实现高频/危险 topic 策略。
- 不做分片重组；第一版要求单个 envelope 不超过 endpoint `mtu()`，超出则发送失败并记录日志。
- 不改变 `MessageHeader` 布局，避免共享内存格式升级风险。
- Gateway 是独立模块；`DDSCore` 只暴露必要内部能力，不承担跨域路由状态。
