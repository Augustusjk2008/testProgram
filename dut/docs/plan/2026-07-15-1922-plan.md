# COM3 控制口修正 Implementation Plan

> **Execution note:** 本方案可在当前会话或由执行代理直接实施，使用复选框跟踪进度。

**Goal:** 将 ECHO 回显画像和 HW_TEST 产品协议服务的板端控制口从 COM2 修正为 COM3，即 `/dev/xdma0`、基地址 `0xC0000`、XDMA event 2，并同步总线链路排除规则、PC 工具、脚本、测试和文档。

**Architecture:** 保持 `XdmaTransport + ComDevice`、三画像结构和产品协议格式不变，只调整应用层固定控制口配置。COM 总线测试继续采用 link 2/3/4/5 对应 COM1/2/3/4，但控制口占用项从 link 3 改为 link 4。

**Tech Stack:** C++20、CMake、AArch64 交叉工具链、PowerShell 5.1、PyQt5/Python 3.8、GoogleTest、pytest。

---

## 目标

1. ECHO 和 HW_TEST 均使用 COM3：

   - XDMA 设备：`/dev/xdma0`
   - user BAR 偏移：`0xC0000`
   - 映射窗口：`0x40000`
   - event：`2`
   - 串口配置：`614400 / 8E1 / 无流控`
   - 中断模式：Level

2. 总线测试映射修正为：

   | link_id | 链路 | HW_TEST 行为 |
   |---:|---|---|
   | 0 | 100M 网口 1 | 保持 |
   | 1 | 100M 网口 2 | 保持 |
   | 2 | COM1 | 可测试 |
   | 3 | COM2 | 可测试 |
   | 4 | COM3 | 控制口占用，返回 `CHANNEL_INVALID` |
   | 5 | COM4 | 可测试 |
   | 6 | SPI | 保持 |

3. 对外入口统一改名为 `Com3Echo`/`com3_echo`，不保留会误导操作者的 COM2 兼容别名。

4. 协议帧、CRC、CSV、构建画像及产物目录保持不变。

#include <optional>

inline constexpr unsigned kControlComIndex = 2;
