# MB_DDF PC 串口回显测试首版实施方案

**目标：** 在 `test_pyqt` 中完成一个 Win7 兼容的单串口测试工具，并为板端 COM1 增加安全、显式启用的 payload 原样回显模式。

**架构：** PC 端使用 PyQt5 自带的 `QtSerialPort` 异步收发，协议解析器逐字节处理；每个串口实例独立持有物理参数和协议配置。板端继续使用 `XdmaTransport + ComDevice`，由 FPGA 完成帧头、长度和 CRC 处理，应用层只回显有效数据。

**技术栈：** Python 3.8.18、PyQt5 5.15.9、Qt 5.15.2、matplotlib 3.3.4、pytest、pytest-qt、AArch64 C++20。

## 协议基线

首版统一采用以下确定值：

```text
线序帧头：55 AA
长度字段：1 字节，表示有效数据长度
有效数据：1..255 字节；不增加流水号，不补齐、不截断
CRC：CRC-16/XMODEM
多项式：0x1021
初值：0x0000
RefIn/RefOut：false
XorOut：0x0000
校验范围：[长度字节] + [有效数据]
CRC 线序：低字节在前
完整格式：[55 AA][LEN][DATA...][CRC_LO CRC_HI]
```

已知测试向量：

```text
DATA：4D 42 31
CRC 输入：03 4D 42 31
CRC：0x89FC
完整帧：55 AA 03 4D 42 31 FC 89
```

硬件文档未明确 CRC 变体，因此端到端外部链路验证是交付门槛。若 FPGA 拒绝上述已知帧，停止交付，依据 IP 核说明或逻辑分析结果修订 CRC 参数、测试向量和 `AGENTS.md`，不得仅放宽 PC 校验。

## 实施步骤

### 1. 固化专用环境入口

- [ ] 在 `requirements-win7.txt` 锁定当前已验证的 PyQt5、Qt、matplotlib、numpy、pytest 和 pytest-qt 版本；不加入缺失且不再需要的 `pyserial`。
- [ ] `run.ps1` 只调用 `C:\Users\JiangKai\.conda\envs\pyqt5_env\python.exe`，设置该环境的 Qt `plugins` 和 `bin` 路径后执行 `python -m test_pyqt`。
- [ ] `run.bat` 作为 Win7 兼容包装调用 `run.ps1`。
- [ ] `main.py` 校验解释器路径和 Python 3.8，路径不符时输出中文错误并退出，禁止静默使用 base/system Python。
- [ ] matplotlib 首版只作为已锁定的后续绘图依赖，不创建图表或空白 Canvas。

### 2. 实现协议模块

- [ ] 在 `app_config.py` 定义不可变的 `ProtocolConfig`、`SerialPortConfig` 和上述默认值；协议配置属于单个串口实例，不设全局可变参数。
- [ ] 先编写 CRC 已知向量、完整帧编码、0/255/256 长度边界、拆包、粘包、噪声、重叠帧头、错误 CRC、超时半帧和错误后恢复测试。
- [ ] 在 `serial_protocol.py` 实现 `crc16_xmodem()`、`encode_frame()` 和增量 `FrameDecoder`。
- [ ] `FrameDecoder` 对 `readyRead` 提供的 chunk 逐字节推进状态机；第二个头字节不匹配时保留可能重叠的首字节。
- [ ] 半帧超过 500 ms 后复位并产生错误事件；CRC 错误不得上报为有效数据。

### 3. 实现独立串口通道

- [ ] `serial_channel.py` 每个 `SerialChannel` 内部持有一个 `QSerialPort`、一个配置对象和一个解析器。
- [ ] 配置映射固定为默认 `614400 / Data8 / EvenParity / OneStop / NoFlowControl`，打开后锁定该通道的配置控件。
- [ ] 使用 `readyRead` 读取当前全部可用字节，再逐字节交给解析器；不使用 GUI 主线程 1 ms 轮询，也不额外建立阻塞线程。
- [ ] 实现发送队列并处理 `write()` 返回失败、部分排队、`bytesWritten` 和 `errorOccurred`。
- [ ] 提供连接、断开、合法帧、协议错误、发送完成和 I/O 错误信号。关闭端口时清空半帧和待发送数据。
- [ ] 构造函数允许注入假串口后端，使测试不依赖真实 COM 设备。

### 4. 实现最小化界面

- [ ] `main_window.py` 首版只实例化一个标记为“板端 COM1”的通道面板。
- [ ] PC 串口下拉框允许手工输入并提供刷新按钮；必须明确区分“板端 COM1”和 Windows 实际出现的 `COMx`。
- [ ] 面板包含端口、波特率、数据位、校验、停止位、连接状态和开关按钮；默认显示 614400、8、Even、1。
- [ ] 串口测试区只提供十六进制有效数据输入和“发送并校验回显”命令，不增加文本模式、连续压力测试或其它硬件功能。
- [ ] 一次只允许一个待判定请求，超时固定 1000 ms；结果分为通过、内容不符、CRC 错误、发送失败和超时。
- [ ] 日志框使用只读 `QPlainTextEdit`，显示毫秒时间、级别、通道、整帧 TX/RX 和错误；最大保留 5000 个文本块并提供清空按钮，不逐字节刷屏。
- [ ] 窗口关闭时取消测试计时器并关闭全部通道，为以后增加第二个 `SerialChannel` 保留列表式管理入口。

### 5. 对齐板端 COM 默认配置

- [ ] 修改 `ComDevice.h`，使 `ComDevice::default_config()` 真正匹配寄存器规范：`byte_format=0xB0`、布局 `0x42/0x42`、线序帧头 `55 AA`、波特率计数 `0x00CA`。
- [ ] 保留正常模式、接收使能和 1 字节长度；回显入口单独把中断模式设为 `Level`、`loopback=false`。
- [ ] 在 `test_com_device.cpp` 断言默认格式、头字节顺序、布局、波特率和 `configure()` 的实际寄存器写入顺序。

### 6. 增加安全的 COM1 回显入口

- [ ] 在 `src/main.cpp` 增加 `MB_DDF_COM1_ECHO=1` 分支；未设置时完整保留当前 DDS/硬件 Demo 行为。
- [ ] 无硬件层构建却请求回显时明确报错退出；不得新增 `/dev/ttyS*` 或 `termios` 路径。
- [ ] 使用 `/dev/xdma0`（允许 `MB_DDF_XDMA_DEVICE` 覆盖）、偏移 `0x40000`、窗口 `0x40000`、event 0 构造 COM1。
- [ ] 打开后保存原 `ComConfig`，应用明确回显配置，依次清错并使能接收；绝不调用锁存式 `reset()`。
- [ ] 使用 255 字节缓冲区和 100 ms 有界等待循环；收到非空 payload 后调用 `send()` 并核对发送长度。
- [ ] `SIGINT/SIGTERM` 只设置退出标志；正常退出和异常路径均尝试恢复保存配置并关闭 Transport。恢复失败返回独立非零退出码。
- [ ] `ProtocolError` 记录后继续接收；Transport、配置、发送等错误视为致命错误。日志只走 `Logger.h` 和 SSH 终端，不写入 COM1。

### 7. 增加安全运行包装

- [ ] `debug.ps1` 增加 `-Com1Echo`，要求同时存在 `-Run`，并禁止与 `-FullHardware` 同时使用。
- [ ] 该开关自动启用硬件层、关闭不需要的 DDS Adapter，并向目标进程传入 `MB_DDF_COM1_ECHO=1`。
- [ ] `debug.bat` 增加 `com1_echo` 包装；保留现有 `run`、`hw_run` 参数和输出格式。
- [ ] 回显入口不得复用 `hw_run`，避免触发 DH 点火和 Flash 写入。

### 8. 更新维护文档

- [ ] `AGENTS.md` 写明专用解释器、依赖版本、QtSerialPort 选择、启动/测试命令、协议线序、单端口独立配置方式、Win7 x64 限制和 COM1 回显安全规则。
- [ ] 明确 Python PC 工具及其单元测试是在 Windows 运行的例外；AArch64 C++ 二进制仍只在目标板执行。
- [ ] `demo-usage.md` 增加显式回显模式、退出方式、恢复边界和“不得使用 `SIGKILL`”说明。
- [ ] `build-and-debug-guide.md` 记录 `-Com1Echo` 与 `debug.bat com1_echo`。
- [ ] `hardware-layer-architecture.md` 记录固定帧参数和 payload 级回显职责边界；`docs/tests/README.md` 增加 PC 测试入口。
- [ ] `.gitignore` 增加 `.pytest_cache/`。
