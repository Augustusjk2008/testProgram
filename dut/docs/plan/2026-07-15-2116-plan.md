**现状结论**

- 模式 1 报 `0x0102` 是板端主动拒绝：`SystemTestProvider.cpp:548-550` 仅接受 `mode == 0`，现有单元测试也固定要求 mode 1 返回 `PARAM_OUT_OF_RANGE`。
- 模式 0 实际已经返回一帧统计响应，包含 8 个抖动桶、平均抖动和最大抖动。PC 收到后立即自动发送 STOP，随后 `main_window.py:600` 清空响应表，导致统计被只有 `status/err_code` 的 STOP ACK 覆盖。
- 当前协议没有周期或异步定时器回告。START 同步执行 `250 us × 250` 次采样，约 62.5 ms 后返回唯一一帧统计。
- 当前 STOP 无法中断 START：协议服务在同一接收线程内同步执行采样，只有 START 完成后才能处理 STOP。

**目标**

1. 让模式 0 的统计结果在 STOP ACK 后仍可见。
2. 明确定义并实现两种负载模式：
   - `mode=0`：无额外负载的基线抖动统计。
   - `mode=1`：统计期间叠加只读 XDMA C2H0 负载。
3. 保持现有单次 START 统计加 STOP ACK 的协议时序，不新增周期回告。
4. 保持 `SystemTestProvider` 不直接依赖 `MB_DDF_HW`。

**实施步骤**

1. 先增加回归测试，锁定当前缺陷：START 响应包含完整统计、STOP ACK 不应覆盖统计表、mode 1 不再被当作非法参数。

2. 在 `SystemTestProvider.h` 定义不包含任何 `MB_DDF_HW` 类型的最小负载接口，支持启动和幂等停止；`SystemTestProvider` 通过非拥有指针接收实现，使 mode 0 和单元测试仍可无硬件构造。

3. 在 `HardwareTestProvider.cpp` 实现 XDMA 负载执行器，并通过现有 `impl_` 注入 `system_`。使用以下只读配置：

   ```cpp
   XdmaConfig{"/dev/xdma0", 0, 0x1000, -1, 0, -1}
   dma_read(0, buffer_64k, 0)
   ```

   每 12 ms 执行一次 64 KiB C2H0 读取，要求返回长度严格等于 65536。只打开 C2H0，不打开 H2C，不执行写入。

4. 不使用参考工程配置中的 `0x80000000` 作为 DMA 地址。该值在旧实现中用于 `_user` 的 mmap 偏移，而参考 CML 调用实际读取偏移为 0；当前已有 DMA 示例也使用 `user_offset=0`。若目标板证明偏移 0 不符合 FPGA 地址规划，必须取得明确的 C2H 地址后修订，不能猜测。

5. 修改定时器处理逻辑：

   - mode 0 直接执行现有 250 次采样。
   - mode 1 先启动负载，采样结束后在发送 START 响应前停止并 `join` 负载线程。
   - mode 大于 1 返回 `0x0102`。
   - mode 1 缺少执行器、打开失败、DMA 失败、短读或线程启动失败返回 `TASK_EXEC_FAILED (0x0203)`。
   - 已有负载未结束时返回 `TASK_BUSY (0x0204)`。
   - 所有退出路径都先停止线程，再关闭 Transport。
   - 删除当前无法通过协议触发的 `timer_stop_requested_` 假取消逻辑。
   - STOP 定义为采样完成后的幂等清理 ACK，不宣称能够中途取消 START。

6. 修改 PC 会话和界面：

   - 将“模式”改为只允许 `0/1` 的下拉选项，并在 `run_test()` 中再次校验，防止代码调用或“执行全部”参数绕过 UI。
   - 保留收到 START 后自动发送 STOP 的现有流程。
   - `MainWindow._on_product_response()` 收到定时器 STOP ACK 时不清空、重画响应表；STOP 成败继续通过测试状态和日志显示。
   - 不改变其他测试响应的覆盖行为。

7. 更新 `codedesign.md`，记录 mode 0/1、12 ms/64 KiB/C2H0/偏移 0、单次统计响应和幂等 STOP 语义，不新增重复文档。
