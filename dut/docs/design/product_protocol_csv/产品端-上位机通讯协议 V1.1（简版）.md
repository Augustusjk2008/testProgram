# 产品端-上位机通讯协议 V1.1（简版）
> 版本：V1.1（2026-07-27）
> 适用范围：产品端（openEuler 测试 daemon）↔ 上位机端（hwtest V2.1）。控制口 COM3
> 固定为 `614400 / 8E1 / 无流控`；惯测输入 COM4 固定为 `921600 / 8E1`。
> 定位：本文只作协议语义参考；本目录 CSV 是字段布局事实源，当前实现与硬件边界以
> `codedesign.md` 为准；当前目录共 37 份 CSV。
>
> 说明：本文替代旧版 `产品端-上位机通讯协议_shturl.` 的冗长描述，只保留实现必需的帧头、指令语义、特殊流程与错误码。具体字节偏移请直接查阅对应 CSV。

## 1. 公共帧头
| 字节 | 字段 | 类型 | 说明 |
|------|------|------|------|
| B1 | sync[0] | CONST | 0x55 |
| B2 | sync[1] | CONST | 0xAA |
| B3 | len | U8 | 数据段长度（version 起至 payload 末尾），按帧档固定为 48 或 123 |
| B4 | version | CONST | 0x11（V1.1） |
| B5 | type_group | U8 | 类型组（模块） |
| B6 | sub_type | U8 | 子类型（指令） |
| B7-8 | seq | U16 | 序列号，响应回显请求值 |
| B9.. | payload | — | 命令载荷，长度由 CSV 定义 |
| 末 2B | crc | U16 | CRC16-CCITT/XMODEM（多项式 0x1021，初值 0x0000，无反射） |
- **大小端**：全部多字节字段小端。
- **CRC 范围**：从 `len`（B3）到 payload 末尾，不含同步字与 CRC 自身。
- **帧长分档**：
  - 统一档：**53B**（`len=48`，payload 43B）。
  - 大帧档：**128B**（`len=123`，payload 118B）。
- **无重发**：CRC 失败或超时静默丢弃/上报通信失败，接收端不主动应答。
- **严格布局**：CSV 的 `index`、`length` 与公共帧头公式必须同时成立，不按字段行顺序容错。

## 2. 指令集
### 2.1 模块划分
| type_group | 模块 | 指令（sub_type） |
|------------|------|------------------|
| 0x01 | 系统监控 | 0x01 SYSTEM_STATUS |
| 0x02 | 存储与性能 | 0x01 MEMPERF_TEST / 0x02 SPI_FLASH_TEST |
| 0x03 | 总线通信 | 0x01 BUS_LOOP_TEST / 0x02 BUS_ECHO_TEST |
| 0x04 | 开关量 | 0x01 DI_READ / 0x02 DO_WRITE |
| 0x05 | 电气健康 | 0x01 ELEC_HEALTH_STATUS |
| 0x06 | DH  | 0x01 DH_PULSE_CONFIG / 0x02 DH_CONTROL |
| 0x07 | 舵机与舵控 | 0x01 HELM_FEEDBACK（主动上送）/ 0x02 HELM_BOARD_TEST / 0x10 HELM_START / 0x11 HELM_STOP |
| 0x08 | 定时器精度 | 0x01 TIMER_JITTER_START / 0x02 TIMER_JITTER_STOP |
| 0x09 | 惯测连续流 | 0x10 IMU_STREAM_START / 0x01 IMU_STREAM_FEEDBACK（主动上送）/ 0x11 IMU_STREAM_STOP |
| 0xFF | 错误应答 | 0x00 ERROR |

### 2.2 通用响应约定
- 响应帧 `type_group/sub_type` 与请求相同，`seq` 回显请求值。
- 响应包含 `status:U8`（0=OK，1=执行失败）和 `err_code:U16`；具体位置以 CSV 为准，
  例如 HELM_START 响应先包含 `helm_version`。
- 写操作（DO_WRITE、HELM_BOARD_TEST、HELM_START/STOP、TIMER_JITTER_STOP、IMU_STREAM_START/STOP）回定长 ACK：status + err_code + 回读/空数据，禁止静默写。
- 错误应答 0xFF/0x00：用于帧级错误（未知 tg/st、`len` 不匹配、版本不支持、参数不可解析），载荷含原 tg/st/seq、err_code、detail。

## 3. 特殊流程
### 3.1 DH 脉宽配置
1. `config_enable=1`：写使能后配置并回读 23 路脉宽，完成后保持使能。
2. `config_enable=0`：忽略请求中的 `pulse_width[]`，只执行失能并回读当前脉宽。
3. “执行全部”先配置 DH0=`80 ms`、DH1..22=`63 ms`，再执行 DH_CONTROL。

### 3.2 DH_CONTROL 1:N 突发
1. 上位机发送一帧 `DH_CONTROL` 请求：
   - `power_enable`：DH 电源总使能（0=断，1=通）。
   - `return_enable`：DH 回线总使能（0=断，1=通）。
   - `channel[0..1]`：23 路 DH 通道位图（有效位 0~22）。
   - `report_count=N`：回告总帧数，默认 50。
   - `interval_us=T`：相邻两次板端实际采样起点的最小间隔，默认 2500 µs。
   - `delay_us=D`：首帧额外等待时间。
2. 产品端按“电源使能 → 回线使能 → Multiple 模式 → 所选通道触发”执行；使能为 0
   且通道非空时仍提交触发，由硬件使能状态决定实际输出。
3. 等待 `D` µs 后采集首帧并立即发送；后续每帧的截止点按“上一帧实际采样起点 + T”
   计算，到期后采样并立即发送。串口发送只占周期余量，不额外叠加到 `T`；发送超出周期时
   不追赶压缩下一帧，实际采样起点间隔仍不小于 `T`。
4. 第 i 帧（i=0..N-1）的 `seq = 请求 seq + i`（U16 回绕）。上位机按 seq 收齐与检丢，**丢帧不重发**。
5. `report_count` 范围为 `1..65535`，`interval_us` 范围为 `2500..65535`，`delay_us`
   范围为 `0..65535`；通道只允许 bit 0..22，其他位返回 `PARAM_OUT_OF_RANGE`。
6. 当前服务在单接收线程内同步完成突发，不要求并行接收其他命令。每帧读取同一份
   ADS1258 快照：`telemetry[0]=raw[1]`，`telemetry[1..22]=raw[4..25]`；板端完成运放
   定标后按 `0.001 V/LSB` 编码。硬件打开/回读异常按 `status_error()` 映射，定点编码
   失败返回 `TASK_EXEC_FAILED`，均不提交部分响应。

### 3.3 舵控板级测试
- `HELM_BOARD_TEST` 请求 B9 低 4 位 `pwm_command_reserved` 必须为 0，高 4 位为四路方向；B10-B13 分别为
  四路 U8 整数占空比，只接受 `0..100%`。板端按
  `raw=(uint64_t(peak_value)*percent+50)/100` 四舍五入换算，四路方向独立写入，四路 PWM
  全部使能，并打开 PWM update、AD7606 采集和滤波。
- 响应回读四路 `pwm_duty_match`、方向、raw duty、peak、四路 AD7606 以及相关使能状态；
  `pwm_duty_match[i]=1` 表示第 i 路 raw duty 与本次百分比换算值精确一致。任一硬件回读
  不一致返回 `REG_RW_FAILED (0x0201)`。已有舵控功能任务活动时返回 `TASK_BUSY`。
- PC 当前导航和“执行全部”使用该命令。命令不自动恢复测试前状态，已写入的 PWM、
  方向和使能状态保持，只能在隔离且允许硬件写入的目标板运行。
- `DO_WRITE` 只映射 DIDO DO0..15，舵 PWM 百分比和方向由 `HELM_BOARD_TEST` 独立完成；
  四路舵 FK 也由该响应的 `helm_AD_value[0..3]` 回传。
- FPGA 原始码按实际测试入口上传：`value_YX` 为 XADC VAUX8（全局 `0x150260`）的
  `Data[15:4]`，位于 `ELEC_HEALTH_STATUS` B31-B32，LSB=`10.09/4096 V/code`；四路舵 FK
  为 AD7606 通道 0..3 的有符号 16 位 raw，位于 `HELM_BOARD_TEST`，LSB=`10/65536 V/code`。
  PC 乘 LSB 得到电压，不丢失 ADC 分辨率。
- ADS1258 由板端按当前临时定标值换算；为避免简版重复维护公式，完整定义统一见
  [`codedesign.md`](codedesign.md) 和 `origin_v3` 生成寄存器表。
- `ELEC_HEALTH_STATUS` 已确认 `c_volt=raw[0]`/`0x80`、`b_volt=raw[2]`/`0x88`、
  `v28_5=raw[3]`/`0x8C`，板端换算后按 `0.01 V/LSB` 编码；`js_5V` 为 XADC
  VAUX0/`0x240`。PC 仅显示 `activate_bits.bit0` 并命名为“BC激活好”；该位来自 DH
  `BatteryStatus` 高 8 位：`0xAA` 为已激活、`0xFF` 为未激活；bit1..7 恒为 0 且不显示，
  低 8 位点火状态忽略。其他高字节值
  返回 `REG_READ_WRITE_FAILED`，不发送部分成功数据。

### 3.4 保留的舵控功能测试
- `HELM_FEEDBACK 0x07/0x01`、`HELM_START 0x07/0x10`、`HELM_STOP 0x07/0x11`
  的扫频协议与双端实现保留，但当前 PC 导航不显示，且“执行全部”不执行。
- **带舵时**：
  1. 上位机发送 `HELM_START`，产品端回 ACK。
  2. 产品端持续主动上送 `HELM_FEEDBACK`（tg=0x07/st=0x01）帧，直至收到 `HELM_STOP`。
  3. 上位机发送 `HELM_STOP`，产品端回 ACK 并停止上送反馈。

### 3.5 惯测连续流

1. 上位机只以 `device_stream` 启动惯测：发送一次 `09/10` 并确认 ACK，随后只读取主动
   `09/01`；停止时发送一次 `09/11` 并确认 ACK，异常收尾不得再发第二次 STOP。
2. COM4 payload 固定为小端 59 字节：`source_seq:U16`、12 个 F32、
   `temperature:S16F`（0.1 ℃/LSB）、`self_test_status:U16`、`work_status:U8`、
   `software_version:U16`、`source_reserved:U16`。帧头、长度和 CRC 已由 FPGA 消费。
3. 每个有效 payload 立即尝试发送完整 128 字节 `09/01`，不得固定 sleep、主动抽样或
   降采样；400 Hz 不保证无损。零有效反馈判失败，至少一帧判通过；流活动时 BUS link 5
   返回 `TASK_BUSY`。`source_seq` 原样记录，不参与连续性判定。

### 3.6 序列号规则
- 普通请求-响应：`seq` 由上位机递增，响应原样回显；上位机按 `(tg, st, seq)` 匹配，丢弃迟到帧。
- `DH_CONTROL` 的第 `i` 帧使用 `请求 seq+i`（U16 回绕）。
- `HELM_FEEDBACK` 没有对应请求：`HELM_START` ACK 回显请求序号，随后反馈帧使用板端独立递增序号，直至 `HELM_STOP`。
- `IMU_STREAM_FEEDBACK` 使用板端独立递增序号；`source_seq` 是普通数据字段。
- ERROR 响应自身的 `seq` 与 `orig_seq` 都使用触发错误的请求序号。

## 4. 错误码表
| err_code | 名称 | 含义 |
|----------|------|------|
| 0x0000 | OK | 成功 |
| 0x0001 | CMD_UNKNOWN | type_group/sub_type 未知或版本不支持 |
| 0x0002 | LEN_MISMATCH | `len` 与 (tg,st) 定值不匹配 |
| 0x0003 | CRC_ERROR | CRC 校验失败（若选择回应） |
| 0x0101 | CHANNEL_INVALID | 通道/链路/test_id 非法 |
| 0x0102 | PARAM_OUT_OF_RANGE | 参数越界 |
| 0x0103 | SAFETY_LIMIT | 预留安全限制；当前实现未返回 |
| 0x0201 | REG_RW_FAILED | FPGA 寄存器访问或硬件回读异常 |
| 0x0202 | MEM_ACCESS_FAILED | 存储器不可访问 |
| 0x0203 | TASK_EXEC_FAILED | 任务流程、超时或数据编码失败 |
| 0x0204 | TASK_BUSY | 任务忙（舵控/定时器/DH/IMU 流已在运行）；IMU 活动时 BUS link 5 返回该错误 |
| 0x0301 | HELM_DDS_FAILED | 预留舵控 DDS 链路错误；当前实现未返回 |
> 注意区分“执行失败”（`status=1, err_code≠0`）与“测试不通过”（执行成功但 `error_count>0` 或结果位图 pass 位为 0）：后者是测试结果，由上位机 criteria 判定，不进错误通道。
